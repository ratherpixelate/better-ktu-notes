Module 4: Introduction to Parallel Processors

Exam-oriented notes for KTU PCITT302, Module 4 (introduction to parallel processors). SISD, MIMD, SIMD and SPMD come first and carry the "Likely exam" chip. Vector processing, multithreading, multicore and the Core i7 case study follow, shorter.

Why multiprocessors, and why parallel programs are hard

DefineNumerical

MultiprocessorA computer built by connecting many smaller processors, instead of one large inefficient one. A cluster is a set of computers connected over a network that works as one large multiprocessor.

Goals and advantages

AdvantageMeaning
Improved performanceMany independent processes run at the same time (process-level parallelism).
Higher throughputMore processes complete per unit time.
Fault toleranceIf one processor fails, the other n − 1 keep running.
ScalabilitySpread the load over more processors as demand grows.
Economies of scaleShared resources make the system cheaper.

Terms

  • Parallel processing: running a single job on multiple processors at the same time. Running many independent jobs is task-level (process-level) parallelism.
  • Multicore processor: a microprocessor with several processors ("cores") on one chip. Multicores are almost always shared memory processors (SMPs), because the cores share one physical address space.
  • Data parallelism: the same operation on many independent data items (SIMD, vector). Task parallelism: different tasks or threads run at the same time (MIMD).

Software against hardware

The challenge is that concurrent software can run on serial or on parallel hardware. We must (1) make naturally sequential software fast on parallel hardware, and (2) make concurrent programs fast as the number of processors grows. Example: a MATLAB matrix multiply is sequential software, and it can run on a serial Pentium 4 or on a parallel Core i7.

Why parallel programs are hard

  • Scheduling, partitioning the work into parallel pieces, load balancing, time to synchronize, and communication overhead.
  • Analogy: 8 reporters writing one story. The pieces must be equal and they must not spend their time talking to each other.
  • Amdahl's Law: even a small sequential part limits the speed-up.
Speed-up = 1 / [ (1 − F) + F / N ] F = fraction that is parallel, N = number of processors

Numerical 1Speed-up of 90 with 100 processors: how much can be sequential?

1/90 = (1 − F) + F/100 → F = (1 − 1/90) / (1 − 1/100) = 0.9989
Sequential part = 1 − F ≈ 0.11% (the textbook rounds to 0.1%)

Numerical 2Add 10 scalar variables (not parallelizable) and add two 10 × 10 matrices (parallelizable). Speed-up with 10 and with 40 processors? Then with 20 × 20 matrices.

  • Strong scaling: speed-up with the problem size fixed. Weak scaling: the problem size grows in proportion to the processors. A bigger problem gives better speed-up.
  • Load balance: in the 20 × 20 case on 40 processors, if one processor gets 5% of the work instead of 2.5%, time = max(380/39, 20) + 10 = 30 and the speed-up falls from 20.5 to 410/30 ≈ 14. At 12.5% it falls to 410/60 ≈ 7.

SISD, MIMD, SIMD, SPMD (and MISD)

Likely examDefineDifferentiateDraw

Classification by the number of instruction streams and data streams (Flynn, 1960s, still used).

ClassMeaningExample
SISDSingle instruction stream, single data stream. A conventional uniprocessor.Intel Pentium 4
SIMDSingle instruction stream, multiple data streams. The same instruction is applied to many data items, as in a vector processor. All units are synchronized and driven by one PC.x86 SSE and AVX, vector processors, GPUs
MIMDMultiple instruction streams, multiple data streams. A multiprocessor. Each processor runs its own instructions on its own data.Intel Core i7 (multicore)
SPMDSingle program, multiple data streams. The normal way to program a MIMD computer: one program runs on all processors, and conditional statements make different processors run different sections.OpenMP or MPI programs
MISDMultiple instruction streams, single data stream. A series of computations on one data stream in a pipelined fashion (parse, decrypt, decompress, search). No longer in use.None today
  • SPMD is a programming model, not a hardware class. The hardware is MIMD.
  • A MIMD can run separate programs on different processors that work together, but programmers normally write one program (SPMD).
  • MIMD runs on multiple processes or threads to keep its processors busy. SIMD gets its parallelism from data.

SIMD against MIMD

SIMDMIMD
ControlOne PC, all units synchronizedA PC per processor, units independent
ParallelismData-levelTask or thread-level
Instruction storageOne copy of the codeShared-memory MIMD needs several instruction caches and a copy of the code in each

NoteThe original motivation for SIMD was to spread the cost of one control unit over dozens of execution units. Each unit still has its own address registers, so different units can use different data addresses. Both points are from the textbook.

SIMD in detail

Likely examExplainNumerical
  • SIMD operates on vectors of data. One SIMD instruction can add 64 numbers by sending 64 data streams to 64 ALUs and producing 64 sums in a single clock cycle.
  • All execution units are synchronized and respond to a single instruction from a single PC. To the programmer it looks close to SISD.
  • A sequential program can be compiled for SISD hardware or for SIMD hardware.
  • Advantage: reduced instruction bandwidth. Only one copy of the code runs everywhere.
  • Works best on arrays in for loops. It needs a lot of identically structured data, called data-level parallelism.
  • Weakest in case or switch statements, where each unit must do a different operation depending on its data. Units with the wrong data are disabled while the others continue. With n cases, SIMD runs at about 1/n of peak.

NumericalA 64-wide SIMD unit executes a switch with 4 cases, and each lane takes one case. Effective rate = 1/4 of peak. In the 64-add example, 64 lanes finish in 1 cycle against 64 cycles on a scalar unit, so a speed-up of 64 when all lanes are used. On the 4-case switch, 64 / 4 = 16 times.

SIMD in x86: multimedia extensions

NoteSubword parallelism for narrow integers inspired MMX (1996). Later came SSE (Streaming SIMD Extensions) and then AVX (Advanced Vector Extensions), which does four 64-bit floating-point operations at once. The register width is coded in the opcode, so each wider generation needs a new set of opcodes. Hundreds of SSE and AVX instructions exist now.

Two interpretations of SIMD are alive today: the multimedia extensions above, and the vector architecture in the next section. The old "array processors" with one ALU per element have faded away.

Vector architecture

ExplainDifferentiateNumerical

Vector architectureInstead of 64 ALUs adding 64 numbers at once, the ALU is pipelined. Collect data from memory into a large set of vector registers, operate on the elements in order using pipelined units, then write the results back to memory.

  • A vector machine might have 32 vector registers, each holding 64 elements of 64 bits. The elements are independent, so they can also be processed in parallel.
  • The number of elements L in a vector register is the vector length. It decides how many operations run in parallel.
  • Vector instructions need the operations to be independent, which is data parallelism. The data sits in vector registers.

Vector against scalar

PropertyWhy it helps
One instruction = a whole loopFetch and decode bandwidth drops a lot.
Results are independentNo data hazards inside one vector instruction.
Hazard check per vector operandChecked once per vector, not once per element. Saves time and energy.
Known memory access patternAdjacent elements: the memory latency is paid once for the whole vector, not per word.
The loop branch is goneNo control hazards from the loop.
OverallBetter power and energy, and easier than MIMD to write efficient code when data-level parallelism exists.

Worked example: DAXPY (Y = a × X + Y, 64 elements)

NoteThis is the textbook example. Vector MIPS uses a "v" suffix. lv and sv load and store a whole vector.

Vector MIPS (6 instructions)Meaning
l.d $f0, a($sp)load scalar a
lv $v1, 0($s0)load vector X
mulvs.d $v2, $v1, $f0vector × scalar
lv $v3, 0($s1)load vector Y
addv.d $v4, $v2, $v3add Y to the product
sv $v4, 0($s1)store the result

Conventional MIPS: 2 set-up instructions plus a loop of 9 instructions (l.d, mul.d, l.d, add.d, s.d, two addiu, subu, bne) run 64 times = 2 + 9 × 64 = 578, which the book calls "almost 600". Vector: 6. In the scalar loop nearly half the instructions are loop overhead, and every add.d waits for a mul.d. In the vector code each instruction stalls only for the first element, so stalls happen once per vector operation, about 64 times less often.

Vector lanes

  • A lane is a parallel pipeline for the vector functional units, with its share of the vector registers (lane 0 holds elements 0, 4, 8 ...).
  • Going from one lane to four cuts the clocks per vector instruction by about 4: 64 elements take 64 cycles on one lane and 16 on four, ignoring start-up. 16 lanes would take 4.
  • More lanes only help if the application and architecture support long vectors.

Vector against multimedia extensions (SSE, AVX)

NoteTextbook comparison:

Vector architectureMultimedia extensions
Operations per instructionDozensA few

  • Strip mining: when a loop is longer than the vector length, wrap it in a loop of full-length vector operations and handle the leftover elements.
  • Why are vector machines rare outside high-performance computing? Large vector state slows context switches, vector page faults are hard to handle, and SIMD extensions gave some of the benefit.

Hardware multithreading

DifferentiateDraw

Hardware multithreadingSeveral threads share the functional units of a single processor in an overlapping way, so the hardware stays busy. When one thread stalls, the processor switches to another.

  • MIMD relies on many processes or threads to keep many processors busy. Multithreading keeps one processor busy.
  • Each thread needs its own copy of the register file and the program counter. Memory is shared through virtual memory.
  • The hardware must switch threads quickly, much faster than an OS process switch (hundreds to thousands of cycles). Switching can be done by changing a pointer to another register set, in one clock cycle.
ThreadProcess
Program counter, register state and stack. A lightweight process. Threads usually share one address space.One or more threads plus the address space and OS state. A process switch normally calls the OS.
Fine-grainedCoarse-grainedSimultaneous (SMT)
When it switchesAfter every instruction (every clock), round-robin, skipping stalled threadsOnly on a long stall, such as a last-level cache missDoes not switch: always issues from several threads in the same cycle
StrengthHides both short and long stallsThread switch need not be very fast, rarely slows a single threadUses ILP and thread-level parallelism together, fills the most slots
WeaknessSlows each individual thread, because a ready thread waits its turnPipeline must be emptied or refilled on a switch, so it does not help with short stallsNeeds a multiple-issue, dynamically scheduled (out-of-order) core
  • SMT builds on a multiple-issue, dynamically scheduled pipeline. Register renaming and dynamic scheduling let instructions from independent threads issue together. The hardware tags each slot and renamed register with its thread.
  • Fine-grained raises total throughput, but each thread takes longer to finish.

NoteIn the textbook, fine-grained multithreading hides more stalls but slows each thread, while coarse-grained is simpler but pays a pipeline start-up cost on each switch. Note that general "fine-grained vs coarse-grained" advantages (flexibility, complexity, throughput) describe the granularity of work, not hardware multithreading. Write the table above in the exam.

NoteNumbers from the textbook: on one Core i7 960 core, which supports two threads, SMT gave an average speed-up of 1.31 on the PARSEC benchmarks and an energy-efficiency improvement of 1.07. A modest cost for a decent gain.

Multicore and other shared memory multiprocessors

DefineDifferentiateNumerical

Shared memory multiprocessor (SMP)A multiprocessor with a single physical address space shared by all processors. Processors communicate through shared variables, using ordinary loads and stores to any location.

  • Programs need not care where their data is, only that they can run in parallel. Any variable is available to any processor.
  • When the address space is common, the hardware usually provides cache coherence to give every processor a consistent view of memory.
  • Nearly all multicore chips are SMPs. The alternative, a separate address space for each processor, is the cluster or message-passing style.
UMANUMA
Memory latencySame for every processor and wordSome accesses are much faster, depending on who asks for which word
WhyOne shared memory behind one networkMemory is split and attached to different processors or memory controllers
ProgrammingEasierHarder
ScalingLimitedScales to larger sizes, lower latency to nearby memory

NoteThree more points. (1) Synchronization: processors sharing data must coordinate, or one will read data before another has finished writing it. A lock lets only one processor at a time use a shared variable. (2) A single large memory is a bottleneck, so memory is spread over several modules behind an interconnection network. (3) In a message-passing multicomputer each node is a full computer with its own private memory, and data is shared by sending messages. A cluster is of this kind.

Worked example: sum 64,000 numbers on 64 processors (UMA)

NoteTextbook example, and a typical SPMD program.

  1. Divide evenly: each processor Pn (0 to 63) sums 1000 numbers, from A[1000·Pn] to A[1000·(Pn+1) − 1], into sum[Pn]. All processors run the same code (SPMD), only Pn differs.
  2. Reduction: add the 64 partial sums by halving. With half = 32, processors 0 to 31 add sum[Pn + 32] into sum[Pn]. Then half = 16, 8, 4, 2, 1. That is 6 steps, log2 64. The result is in sum[0].
  3. Synchronize between steps (a barrier), so a processor does not read a partial sum before it is written.

Time ≈ 1000 additions + 6 reduction steps, against 64,000 additions on one processor. In OpenMP the same program is a #pragma omp parallel for loop plus a reduction(+ : FinalSum) clause.

Case study: Intel Core i7

Ridge point = 51.2 / 16.4 ≈ 3.1 FLOP/byte (the GTX 280 GPU: 78 / 127 ≈ 0.6)
At 0.5 FLOP/byte: min(51.2, 16.4 × 0.5) = 8.2 GFLOP/s, memory bound (the book says about 8)
At 4 FLOP/byte: min(51.2, 16.4 × 4) = 51.2 GFLOP/s, compute bound

Core i7 against a GPU

  • Intel researchers compared the i7 960 with the NVIDIA GTX 280 GPU on 14 kernels. The GPU ran from 2.0 times slower to 15.2 times faster.
  • The GPU has 4.4 times the memory bandwidth (141 against 32 GB/s), so memory-bound kernels favour it. Caches and cache blocking help the i7, because they can turn a kernel from memory bound to compute bound.
  • Gather-scatter addressing helps the GPU a lot, and the i7's SSE lacks it. Synchronization (atomic updates) can be a big cost on the i7.
  • The book's point is not who wins, but which architecture feature matters for which workload.

NoteSources differ a little on the i7 960 numbers: transistors (700 M against 731 M) and L1 size (64 KB per core as one total, against 32 + 32 KB). Both are given where they occur.

One-page cheat sheet

Revise the night before

Flynn

  • SISD: 1 instruction, 1 data. Uniprocessor
  • SIMD: 1 instruction, many data. Vector, SSE, GPU
  • MIMD: many instructions, many data. Multicore
  • MISD: none today
  • SPMD: one program on all MIMD cores

SIMD

  • One PC, units synchronized
  • One copy of the code
  • Best on array loops (data-level parallelism)
  • case/switch with n cases: 1/n of peak

MIMD

  • PC per core, own instructions, own data
  • Needs threads or processes
  • Sync and communication cost

Vector

  • Vector registers (32 × 64 elements × 64 bit)
  • Pipelined units, lanes
  • One instruction = a loop. DAXPY: 6 against 578
  • No hazards inside a vector, no loop branch
  • Gather-scatter, strided, strip mining

Multithreading

  • Per-thread PC and registers
  • Fine: switch every instruction
  • Coarse: switch on long stall
  • SMT: several threads in one cycle (i7 gain 1.31)

Shared memory

  • One physical address space, cache coherence
  • UMA: uniform latency. NUMA: near is faster, scales more
  • Locks for sync. 64,000 numbers: 1000 each, 6 reduction steps

Amdahl

  • Speed-up = 1 / [(1 − F) + F/N]
  • 90× on 100 CPUs: 0.1% sequential
  • Bigger problem, better speed-up (strong against weak scaling)
  • Load imbalance: 20.5 → 14 → 7

Core i7 960

  • 4 cores, 8 threads, 3.2 GHz, 45 nm, 130 W
  • L2 256 KB per core, L3 8 MB shared
  • SSE: 4 SP or 2 DP per instruction
  • 51 DP and 102 SP GFLOP/s, 32 GB/s memory

Likely questions with answer outlines

The first five are the likely ones
Explain Flynn's classification: SISD, SIMD, MISD and MIMD, with a neat diagram and one example each. (7)

2 by 2 grid of instruction streams against data streams, a line of definition for each, Pentium 4, SSE or vector, no example for MISD, Core i7. See Flynn.

Differentiate SIMD and MIMD. (3 or 7)

Use the table: control, parallelism, code copies, best use, weak point. Add the SIMD and MIMD figure. See Flynn.

What is SPMD? How is it related to MIMD? (3)

One program runs on all processors of a MIMD machine, and conditionals select different sections. It is a programming model, the normal way to program MIMD. Example: the 64,000-number sum. See Flynn and Shared memory.

Explain SISD and SIMD architectures. Why does SIMD slow down on case statements? (7)

SISD as the uniprocessor. SIMD: one PC, many ALUs, one code copy, data-level parallelism, works on array loops. Units with the wrong data are disabled, so n cases give 1/n of peak. See SIMD.

What are the goals and advantages of multiprocessors? Why is it hard to write parallel programs? (7)

Five advantages, then scheduling, partitioning, load balancing, synchronization, communication. Add Amdahl's Law and the 90 times on 100 processors example. See Why multiprocessors.

Explain vector architecture. Compare DAXPY on a scalar and on a vector processor. (7)

Vector registers and pipelined units, the six-instruction vector code against 578 scalar instructions, fewer hazards and branches, lanes. See Vector.

Compare vector processors with scalar processors and with multimedia SIMD extensions. (7)

The two tables: one instruction = a loop, no hazards inside a vector, memory latency paid once; vector length register, strided and gather-scatter access. See Vector.

What is hardware multithreading? Explain fine-grained, coarse-grained and simultaneous multithreading. (7)

Definition, per-thread PC and registers, the comparison table, and the issue-slot figure. Say that SMT gave 1.31 on a Core i7 core. See Multithreading.

Define a shared memory multiprocessor. Differentiate UMA and NUMA. (3 or 7)

Single physical address space, communication by loads and stores, cache coherence. UMA table against NUMA. See Shared memory.

What is a multicore processor? How does it differ from a cluster? (3)

Several cores on one chip sharing a physical address space (SMP). A cluster is separate computers on a network with their own memories, sharing data by messages. See Why multiprocessors and Shared memory.

A program has 99.9% parallel code. What speed-up can 100 processors give? A fixed problem against a larger one? (7)

Speed-up = 1 / (0.001 + 0.999/100) = 91. Then the 10 and 40 processor tables (5.5, 8.8, 8.2, 20.5) and the load-balance drop to 14 and 7. See Why multiprocessors.

Write a case study of the Intel Core i7: architecture and how it uses parallelism. (7)

Four cores (MIMD), SSE (SIMD), two threads per core (SMT), shared L3 and memory, specifications table, and the roofline or the GPU comparison. See Core i7.
