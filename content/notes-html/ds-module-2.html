Linear search

DefineAlgorithmNumericalPast paper

Linear (sequential) searchCheck the elements one by one from the start until the key is found or the end of the list is reached. It works on unsorted data.

Algorithm: LinearSearch (a, n, key)

  1. Start.
  2. Set i = 0.
  3. While i is less than n, repeat steps 4 and 5.
  4. If a[i] is equal to key, print "Found at position i + 1" and stop.
  5. Increase i by 1.
  6. Print "Key not found".
  7. Stop.

Example (May 2026): search 40 in 12, 25, 18, 40, 55, 30

40 is found at index 3 (position 4) after 4 comparisons. If the key were 99, all 6 elements would be compared and the search would fail.

CaseComparisonsComplexity

Average caseabout n/2O(n)
Worst casen (key is last or missing)O(n)

Extra space: O(1). It needs no sorting and works on arrays and linked lists.

C function (compiled and tested)
int linear_search(int a[], int n, int key) {
    for (int i = 0; i < n; i++)
        if (a[i] == key) return i;
    return -1;
}

Binary search

DefineAlgorithmNumericalPast paper

Binary searchSearches a sorted array by comparing the key with the middle element and throwing away half of the array each time.

  • The array must be sorted.
  • If key = a[mid], found. If key < a[mid], search the left half. If key > a[mid], search the right half.

Algorithm: BinarySearch (a, n, key)

  1. Start.
  2. Set low = 0 and high = n − 1.
  3. While low is less than or equal to high, repeat steps 4 to 6.
  4. Set mid = (low + high) / 2 (integer division).
  5. If a[mid] is equal to key, print "Found at position mid + 1" and stop.
  6. If key is less than a[mid], set high = mid − 1. Otherwise set low = mid + 1.
  7. Print "Key not found".
  8. Stop.

Recursive form: BinarySearch (a, low, high, key)

  1. If low is greater than high, return −1 (not found).
  2. Set mid = (low + high) / 2.
  3. If a[mid] is equal to key, return mid.
  4. If key is less than a[mid], return BinarySearch (a, low, mid − 1, key).
  5. Otherwise return BinarySearch (a, mid + 1, high, key).

Example: sorted array 11, 22, 33, 44, 55, 66, 77, 88 (index 0 to 7)

For n = 1024 at most 11 comparisons are needed, against up to 1024 for linear search. Extra space: O(1) for the loop form, O(log n) for the recursive form (call stack).

NoteWith very large arrays, (low + high) can overflow an int. The safe form is mid = low + (high − low) / 2. Binary search also needs random access, so it is not suitable for a linked list.

C function (compiled and tested)
int binary_search(int a[], int n, int key) {
    int low = 0, high = n - 1;
    while (low <= high) {
        int mid = (low + high) / 2;
        if (a[mid] == key) return mid;
        else if (key < a[mid]) high = mid - 1;
        else low = mid + 1;
    }
    return -1;
}

int binary_search_rec(int a[], int low, int high, int key) {
    if (low > high) return -1;
    int mid = (low + high) / 2;
    if (a[mid] == key) return mid;
    if (key < a[mid]) return binary_search_rec(a, low, mid - 1, key);
    return binary_search_rec(a, mid + 1, high, key);
}

Bubble sort

DefineAlgorithmNumericalPast paper

Sorting termsPass: one sweep over the data. In place: uses only O(1) extra memory. Stable: equal keys keep their original order. Internal sorting: all data fits in main memory (all the sorts on this page).

Bubble sortRepeatedly compares adjacent elements and swaps them if they are out of order. After pass 1 the largest element has "bubbled" to the end, after pass 2 the second largest is in place, and so on.

Algorithm: BubbleSort (a, n)

  1. Start.
  2. Repeat steps 3 to 6 for pass = 1 to n − 1.
  3. Set swapped = 0.
  4. Repeat step 5 for j = 0 to n − pass − 1.
  5. If a[j] is greater than a[j + 1], swap them and set swapped = 1.
  6. If swapped is still 0, the array is sorted. Go to step 7.
  7. Stop.

Example (May 2026): 45, 12, 78, 23, 56

PassComparisons and swapsArray after the pass
145 > 12 swap, 45 < 78 no, 78 > 23 swap, 78 > 56 swap12 45 23 56 78
212 < 45 no, 45 > 23 swap, 45 < 56 no12 23 45 56 78
312 < 23, 23 < 45 : no swap, stop12 23 45 56 78

Sorted: 12, 23, 45, 56, 78. This took 3 passes, 4 + 3 + 2 = 9 comparisons and 4 swaps (without the swapped flag it would run all 4 passes, 10 comparisons).

Time complexity (answer for the 5-mark question)

CaseWhyComplexity
Worst (reverse order)n − 1 passes, pass k does n − k comparisons: (n − 1) + (n − 2) + ... + 1 = n(n − 1)/2O(n²)
Averageabout n²/4 swaps and still about n²/2 comparisonsO(n²)
Best (already sorted)one pass of n − 1 comparisons, no swap, stop (with the flag)O(n)

Space O(1). Bubble sort is stable and in place. Measured on 64 sorted numbers: 63 comparisons. On 64 reversed numbers: 2016 = 64·63/2 comparisons.

Common mistakeSome books (and some answer keys) leave out the swapped flag. Then the best case is also O(n²). Say in your answer which version you are writing. With the flag the best case is O(n).

C function (compiled and tested)
void bubble_sort(int a[], int n) {
    for (int pass = 0; pass < n - 1; pass++) {
        int swapped = 0;
        for (int j = 0; j < n - 1 - pass; j++)
            if (a[j] > a[j + 1]) {
                int t = a[j]; a[j] = a[j + 1]; a[j + 1] = t; swapped = 1;
            }
        if (!swapped) break;
    }
}

Selection sort

DefineAlgorithmNumericalPast paper

Selection sortIn each pass, select the smallest element of the unsorted part and swap it into the next position of the sorted part.

Algorithm: SelectionSort (a, n)

  1. Start.
  2. Repeat steps 3 to 6 for i = 0 to n − 2.
  3. Set min = i.
  4. Repeat step 5 for j = i + 1 to n − 1.
  5. If a[j] is less than a[min], set min = j.
  6. Swap a[i] and a[min].
  7. Stop.

void selection_sort(int a[], int n) {
    for (int i = 0; i < n - 1; i++) {
        int min = i;
        for (int j = i + 1; j < n; j++)
            if (a[j] < a[min]) min = j;
        int t = a[i]; a[i] = a[min]; a[min] = t;
    }
}

Insertion sort

DefineAlgorithmNumericalPast paper

Insertion sortBuilds the sorted array one element at a time, like sorting playing cards in your hand. Take the next element (the key) and insert it into its correct place in the sorted part on its left, shifting larger elements one place right.

Algorithm: InsertionSort (a, n)

  1. Start.
  2. Repeat steps 3 to 5 for i = 1 to n − 1.
  3. Set key = a[i] and j = i − 1.
  4. While j is at least 0 and a[j] is greater than key, set a[j + 1] = a[j] and decrease j by 1.
  5. Set a[j + 1] = key.
  6. Stop.

Example: 31, 25, 12, 22, 11

Sorted: 11, 12, 22, 25, 31. 10 comparisons and 9 shifts.

CaseComplexity
Best (already sorted)O(n): one comparison per element (63 for 64 sorted numbers)
Average and worst (reverse order)O(n²) (2016 comparisons for 64 reversed numbers)
Space and stabilityO(1), in place, stable

Insertion sort is fast on small or nearly sorted data, which is why faster sorts use it for small sub-arrays.

C function (compiled and tested)
void insertion_sort(int a[], int n) {
    for (int i = 1; i < n; i++) {
        int key = a[i], j = i - 1;
        while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; j--; }
        a[j + 1] = key;
    }
}

Quick sort (recursive)

DefineAlgorithmNumericalLikely exam

Quick sortA divide and conquer sort. Pick a pivot, partition the array so that smaller elements are on its left and larger on its right (the pivot is now in its final place), then sort the two sides recursively.

Algorithm: QuickSort (a, low, high)

  1. Start.
  2. If low is greater than or equal to high, return (zero or one element is already sorted).
  3. Call Partition (a, low, high) and store the pivot position in p.
  4. Call QuickSort (a, low, p − 1).
  5. Call QuickSort (a, p + 1, high).
  6. Stop.

Partition (a, low, high), with the first element as pivot

  1. Set pivot = a[low], left = low + 1 and right = high.
  2. Move left to the right while left ≤ right and a[left] ≤ pivot.
  3. Move right to the left while a[right] > pivot.
  4. If left < right, swap a[left] and a[right], then go to step 2.
  5. Otherwise swap a[low] and a[right] and return right. This is the final position of the pivot.

Common mistakeBooks use different partition schemes (first element, last element or middle element as pivot, and the Hoare or Lomuto way of scanning). The final sorted answer is the same but the intermediate arrays differ. Name your pivot choice and follow it. This page uses the first element as pivot.

NoteA random pivot or the median of three (first, middle, last) makes the worst case very unlikely on sorted data.

C function (compiled and tested)
int partition(int a[], int low, int high) {
    int pivot = a[low], left = low + 1, right = high;
    while (1) {
        while (left <= right && a[left] <= pivot) left++;
        while (a[right] > pivot) right--;
        if (left < right) { int t = a[left]; a[left] = a[right]; a[right] = t; }
        else break;
    }
    a[low] = a[right]; a[right] = pivot;
    return right;
}

void quick_sort(int a[], int low, int high) {
    if (low < high) {
        int p = partition(a, low, high);
        quick_sort(a, low, p - 1);
        quick_sort(a, p + 1, high);
    }
}

Merge sort (recursive)

DefineAlgorithmDrawPast paper

Merge sortA divide and conquer sort. Divide the array into two halves, sort each half recursively, then merge the two sorted halves into one sorted array.

Algorithm: MergeSort (a, low, high)

  1. Start.
  2. If low is greater than or equal to high, return (one element is sorted).
  3. Set mid = (low + high) / 2.
  4. Call MergeSort (a, low, mid).
  5. Call MergeSort (a, mid + 1, high).
  6. Call Merge (a, low, mid, high).
  7. Stop.

Merge (a, low, mid, high)

  1. Copy a[low] to a[mid] into array L and a[mid + 1] to a[high] into array R.
  2. Set i = 0, j = 0 and k = low.
  3. While both L and R have elements left: if L[i] ≤ R[j], set a[k] = L[i] and increase i. Otherwise set a[k] = R[j] and increase j. Increase k by 1.
  4. Copy any elements left in L to a.
  5. Copy any elements left in R to a.
  6. Stop.

Using L[i] ≤ R[j] (not <) takes the left element first when keys are equal, which keeps the sort stable.

Example: 38, 27, 43, 3, 9, 82, 10

Complexity (answer for the 5-mark question)

CaseComplexity
Best caseO(n log n)
Average caseO(n log n)
Worst caseO(n log n)
Extra spaceO(n) for the temporary arrays (not in place)
StabilityStable
Why: halving gives log n levels (n = 8: 3 levels). Merging all the parts on one level costs n.
T(n) = 2T(n/2) + n gives T(n) = n log n. Same for every input order.

NoteThe syllabus says detailed analysis is not required, so the level-by-level argument above is enough. Merge sort is good for linked lists and large data, but its O(n) extra memory is its main cost compared with quick sort and heap sort.

C function (compiled and tested)
void merge(int a[], int low, int mid, int high) {
    int n1 = mid - low + 1, n2 = high - mid;
    int *L = malloc(n1 * sizeof(int)), *R = malloc(n2 * sizeof(int));
    for (int i = 0; i < n1; i++) L[i] = a[low + i];
    for (int j = 0; j < n2; j++) R[j] = a[mid + 1 + j];
    int i = 0, j = 0, k = low;
    while (i < n1 && j < n2) a[k++] = (L[i] <= R[j]) ? L[i++] : R[j++];
    while (i < n1) a[k++] = L[i++];
    while (j < n2) a[k++] = R[j++];
    free(L); free(R);
}

void merge_sort(int a[], int low, int high) {
    if (low < high) {
        int mid = (low + high) / 2;
        merge_sort(a, low, mid);
        merge_sort(a, mid + 1, high);
        merge(a, low, mid, high);
    }
}

Heap sort

DefineAlgorithmDrawLikely exam

HeapA complete binary tree in which every parent is larger than or equal to its children (max-heap). The largest element is therefore at the root. A heap is stored in an array: for index i, the children are 2i + 1 and 2i + 2, and the parent is ⌊(i − 1) / 2⌋.

Heap sortFirst build a max-heap from the array. Then repeatedly swap the root (largest) with the last element of the heap, shrink the heap by one and restore the heap property. The sorted part grows from the right.

Algorithm: HeapSort (a, n)

  1. Start.
  2. Build a max-heap: for i = n / 2 − 1 down to 0, call Heapify (a, n, i).
  3. Repeat steps 4 and 5 for end = n − 1 down to 1.
  4. Swap a[0] (the largest) and a[end].
  5. Call Heapify (a, end, 0) to restore the heap in the first end elements.
  6. Stop.

Heapify (a, n, i): move a[i] down until the heap property holds

  1. Set largest = i, left = 2i + 1 and right = 2i + 2.
  2. If left < n and a[left] > a[largest], set largest = left.
  3. If right < n and a[right] > a[largest], set largest = right.
  4. If largest is not i, swap a[i] and a[largest] and call Heapify (a, n, largest).
  5. Stop.

Example: 12, 11, 13, 5, 6, 7

Build the max-heap. Heapify index 2 (13 with child 7): no change. Index 1 (11 with children 5, 6): no change. Index 0 (12 with children 11, 13): swap 12 and 13, giving 13 11 12 5 6 7.

C function (compiled and tested)
void heapify(int a[], int n, int i) {
    while (1) {
        int largest = i, l = 2 * i + 1, r = 2 * i + 2;
        if (l < n && a[l] > a[largest]) largest = l;
        if (r < n && a[r] > a[largest]) largest = r;
        if (largest == i) return;
        int t = a[i]; a[i] = a[largest]; a[largest] = t;
        i = largest;
    }
}

void heap_sort(int a[], int n) {
    for (int i = n / 2 - 1; i >= 0; i--) heapify(a, n, i);
    for (int end = n - 1; end > 0; end--) {
        int t = a[0]; a[0] = a[end]; a[end] = t;
        heapify(a, end, 0);
    }
}

Hashing and hash tables

DefineShort notePast paper

HashingA technique that converts a key into an array index directly using a hash function, so that a record can be stored and found without searching. The array is the hash table.

index = h(key), 0 ≤ h(key) ≤ m − 1 (m = size of the table)

CollisionTwo different keys give the same index: h(k1) = h(k2). Hash tables must have a collision resolution technique.

Need for hash tables (May 2026)

StructureSearchInsertDelete
Unsorted arrayO(n)O(1) at the endO(n)
Sorted arrayO(log n)O(n)O(n)
Linked listO(n)O(1) at the frontO(n)
Hash tableO(1) on averageO(1) on averageO(1) on average
  • Searching, inserting and deleting take constant time on average, no matter how many records there are.
  • Worst case is O(n) if every key collides, so the hash function and the collision method matter.
  • Used for symbol tables in compilers, database indexes, caches, dictionaries and sets.

A good hash function

  • Fast to compute.
  • Gives the same index for the same key every time.
  • Spreads keys uniformly over 0 to m − 1, so few collisions.
  • Uses all parts of the key.

1. Division method

Divide the key by the table size m and use the remainder. Fast and simple. Choose m as a prime. A bad m (a power of 2 or 10) makes the index depend only on the last few digits or bits of the key.

h(k) = k mod m
Example: m = 11. h(1234) = 1234 mod 11 = 2 (1234 = 112 × 11 + 2)

2. Multiplication method

Steps

  1. Multiply the key k by a constant A (0 < A < 1).
  2. Take the fractional part of k × A.
  3. Multiply it by m and take the floor.
h(k) = ⌊ m × ( k·A mod 1 ) ⌋ A ≈ (√5 − 1)/2 = 0.6180339887 (suggested by Knuth)
Example: k = 100, m = 20. k·A = 61.8034, fractional part 0.8034, × 20 = 16.07, h(100) = 16
Example: k = 123456, m = 10000. k·A = 76300.0041, fractional part 0.0041, × 10000 = 41.15, h(123456) = 41

Here the value of m is not critical, so m can be a power of 2.

3. Mid-square method

Steps

  1. Square the key.
  2. Take the middle r digits of the square as the index. The table size is 10r.
Example: k = 4567, r = 2 (table size 100)
4567² = 20857489 (8 digits). The middle two digits are the 4th and 5th: 20 8 57 489. h(4567) = 57
Example: k = 123, r = 3 (table size 1000)
123² = 15129. The middle three digits are 5, 1, 2. h(123) = 512

Why it works: the middle digits depend on all digits of the key. The ends of a square depend only on the end digits of the key.

4. Folding method

Split the key into parts of equal length (the last part may be shorter), add the parts, and drop the final carry if the sum is longer than the index.

TypeHowExample: k = 123456789, parts of 3 digits, table size 1000
Shift foldingadd the parts as they are123 + 456 + 789 = 1368. Drop the carry: 368
Boundary foldingreverse every second part, then add123 + 654 + 789 = 1566. Drop the carry: 566

56 + 78 = 134, drop the carry: h(5678) = 34

Common mistakeBooks differ on small details. Mid-square: when the square has an odd number of digits and you need an even number of them (for example 1234² = 1522756, 7 digits, r = 2), some books take the 4th and 5th digits (27) and others the 3rd and 4th (22). Folding: some books take the sum mod the table size and others just drop the carry. State the digits you take and the rule you follow.

NoteThe multiplication and folding examples with the long keys come from a published data-structures course page. Other methods you may see: digit analysis (keep the digits that spread the known keys best) and the radix or polynomial method for strings.

Closed hashing and linear probing

DefineAlgorithmNumericalDrawbacksPast paper

Closed hashing (open addressing)All keys are stored inside the table itself. If the home slot is taken, probe other slots in a fixed order until a free one is found.

Linear probingOn a collision try the next slot, then the next, wrapping around at the end of the table.

h(k, i) = ( h(k) + i ) mod m i = 0, 1, 2, ...

Insert (T, m, key)

  1. Set home = key mod m and i = home.
  2. If T[i] is empty or marked deleted, store key in T[i] and stop.
  3. Set i = (i + 1) mod m.
  4. If i is equal to home, print "Table full" and stop. Otherwise go to step 2.

Search (T, m, key)

  1. Set home = key mod m and i = home.
  2. If T[i] is empty, print "Not found" and stop.
  3. If T[i] is equal to key, print "Found at slot i" and stop.
  4. Set i = (i + 1) mod m.
  5. If i is equal to home, print "Not found" and stop. Otherwise go to step 2.

The keys 49, 58 and 69 are all stored far from their home slots. Searching 69 takes 4 probes. Searching a missing key such as 99 (home slot 9) probes slots 9, 0, 1, 2 and stops at the empty slot 3: 5 probes.

Drawbacks of linear probing

  • Primary clustering: occupied slots form long runs. A key that hashes anywhere into a run is added to its end, so the run keeps growing. In the example above, 49, 58 and 69 all pile up behind 89.
  • Long probe sequences as the table fills: searches (especially for missing keys) slow down sharply (see the load factor section).
  • Deletion is awkward. You cannot just empty a slot, because a search stops at an empty slot and would lose keys stored beyond it. A deleted slot must be marked as deleted, which still adds to the length of searches.
  • The table can become full. There are only m slots, so at most m keys.

Check of the deletion problem: after deleting 49 and marking slot 0 as deleted, searching 69 still finds it. If slot 0 were simply made empty, the search for 69 stops there and wrongly says "not found". Both cases were run.

Common mistakeNaming differs between books. This page follows the KTU syllabus: closed hashing = open addressing (keys stay in the table, as in linear probing) and open hashing = separate chaining (keys go in lists outside the table). A few books use the words the other way round, so write the description along with the name.

C functions for linear probing, with lazy deletion (compiled and tested)
#define M 10
#define EMPTY -1
#define DELETED -2
int hash(int key) { return key % M; }

int lp_insert(int t[], int key) {
    int h = hash(key);
    for (int i = 0; i < M; i++) {
        int s = (h + i) % M;
        if (t[s] == EMPTY || t[s] == DELETED) { t[s] = key; return s; }
    }
    return -1;                       /* table full */
}

int lp_search(int t[], int key) {
    int h = hash(key);
    for (int i = 0; i < M; i++) {
        int s = (h + i) % M;
        if (t[s] == EMPTY) return -1;
        if (t[s] == key) return s;
    }
    return -1;
}

int lp_delete(int t[], int key) {
    int s = lp_search(t, key);
    if (s >= 0) t[s] = DELETED;
    return s;
}

Open hashing: separate chaining

DefineAlgorithmDrawLikely exam

Separate chainingEach slot of the table holds a linked list of all the keys that hash to it. A collision simply adds another node to the list.

Insert (T, key)

  1. Set i = key mod m.
  2. Search the list T[i] for key. If it is already there, stop.
  3. Create a new node holding key.
  4. Add the node at the end of the list T[i] (adding at the front is also common and is O(1)).

Search (T, key)

  1. Set i = key mod m.
  2. Walk down the list T[i], comparing each node with key.
  3. If a node holds key, print "Found" and stop.
  4. If the end of the list is reached, print "Not found".
  • Delete: find the node in the list and unlink it. Nothing special is needed.
  • Cost: the average list length is the load factor α = n / m, so search takes O(1 + α) on average.
  • The table never gets full, and α can be greater than 1.

Remedies for clustering: random, quadratic and double hashing

DefineNumericalLikely examPast paper

Random probing

Random probingThe probe sequence is produced by a pseudo-random number generator. The generator is started with the same seed for every key, so a search repeats exactly the sequence used to insert.

h(k, i) = ( h(k) + ri ) mod m r1, r2, ... = fixed pseudo-random numbers

It removes primary clustering because consecutive probes are scattered. Example with m = 10 and the fixed sequence 5, 2, 8, 1, ... (illustrative): 49 (home 9, taken) tries 9 + 5 = 14, so slot 4. 58 (home 8, taken) tries 8 + 5 = 13, so slot 3. 69 (home 9, taken) tries slot 4 (taken), then 9 + 2 = 11, so slot 1.

Quadratic probing (November 2025)

Quadratic probingOn a collision try the slots at distances 1², 2², 3², ... from the home slot instead of 1, 2, 3.

h(k, i) = ( h(k) + i² ) mod m i = 0, 1, 2, ... (f(i) = i²)

Double hashing

Double hashingA second hash function h₂ decides the step size, so different keys with the same home slot follow different probe sequences.

h(k, i) = ( h1(k) + i × h2(k) ) mod m
h1(k) = k mod m, h2(k) = R − ( k mod R ) R is a prime smaller than m, h2(k) is never 0

Load factor and rehashing

DefineNumericalLikely exam

Load factorα = n / m, where n is the number of keys stored and m is the table size. It measures how full the table is.

  • Open addressing: α can never exceed 1. Keep it below about 0.5 to 0.7.
  • Chaining: α is the average list length and can exceed 1. Keep it around 1 or below.

Why performance falls as α grows (linear probing)

Expected probes, successful search ≈ ½ ( 1 + 1 / (1 − α) )
Expected probes, unsuccessful search ≈ ½ ( 1 + 1 / (1 − α)² )

A simulation with random keys in a 2003-slot table gave 1.49 and 2.46 at α = 0.5, and 2.14 and 5.90 at α = 0.7, which agrees with the formulas. They are for understanding, not for memorising.

RehashingWhen the load factor passes a limit, build a larger table (about twice the size, rounded up to a prime) and insert every existing key again using the hash function with the new table size.

Rehash

  1. Create a new table of about twice the size (next prime).
  2. For every key in the old table, compute h(key) with the new m and insert it into the new table.
  3. Discard the old table.

NumericalTable of size 7 using linear probing holds 15, 22, 36 and 29. Load factor = 4/7 = 0.57, above the limit 0.5, so rehash into size 17.

Table sizeSlots
Before7slot 1: 15, slot 2: 22, slot 3: 36, slot 4: 29 (all four have home slot 1 and pile up)
After1715 mod 17 = 15, 22 mod 17 = 5, 36 mod 17 = 2, 29 mod 17 = 12. Each key is alone in its slot
  • The keys must be re-hashed, not just copied, because h(k) = k mod m changes when m changes.
  • One rehash costs O(n), but it happens rarely, so the average cost per insertion stays O(1) (amortised).

NoteThe limits quoted (0.5 for quadratic probing, about 0.7 for linear probing, and the 0.75 used in some library hash maps for chaining) are rules of thumb. Your answer only needs to say that rehashing starts when α crosses a chosen threshold.

One-page cheat sheet

Revise the night before

Searching

  • Linear: O(n), any order
  • Binary: O(log n), sorted only
  • mid = (low + high) / 2
  • key < a[mid]: high = mid − 1, else low = mid + 1

Simple sorts (O(n²))

  • Bubble: swap adjacent, flag gives best O(n), stable
  • Selection: pick min, always n(n−1)/2 comparisons, not stable
  • Insertion: insert key into sorted part, best O(n), stable

Fast sorts

  • Merge: O(n log n) always, O(n) space, stable
  • Quick: avg O(n log n), worst O(n²) (sorted, first pivot), not stable
  • Heap: O(n log n) always, in place, not stable
  • Heap: children 2i+1, 2i+2

Hash functions

  • Division: k mod m (m prime)
  • Multiplication: ⌊m·frac(kA)⌋, A = 0.618...
  • Mid-square: middle digits of k²
  • Folding: add parts (shift) or reverse alternate parts (boundary)

Collisions

  • Linear: (h + i) mod m, primary clustering
  • Quadratic: (h + i²) mod m, secondary clustering
  • Double: (h₁ + i·h₂) mod m, no clustering
  • Chaining: list per slot, O(1 + α)

Load factor

  • α = n / m
  • Open addressing: α ≤ 1
  • Rehash: new table about 2m (prime), re-insert all keys with the new m

Worked answers

  • Selection 45 23 50 32 17 gives 17 23 32 45 50
  • Bubble 45 12 78 23 56 gives 12 23 45 56 78 in 3 passes
  • Quadratic, m = 7: 22 at 1, 30 at 2, 50 at 5
  • Search 40 in 12 25 18 40 55 30: position 4
