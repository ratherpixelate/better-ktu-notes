Boolean algebra: operations, axioms, theorems

DefineDifferentiateLikely exam

Boolean algebraAn algebra whose variables take only two values, 0 and 1. Every function is built from three basic operations: AND (·), OR (+) and NOT (′ or a bar). NAND, NOR, XOR and XNOR are derived from them.

Operations

ABAND A·BOR A+BNANDNORXOR A⊕BXNOR
00001101
01011010
10011010
11110001
NOT: 0' = 1, 1' = 0
XOR: A ⊕ B = A'B + AB'
XNOR: (A ⊕ B)' = AB + A'B'

Axioms

No.AxiomStatement
1Boolean valuesA variable has only two possible values, 0 or 1.
2Logical negation0' = 1 and 1' = 0.
3Logical product (AND)A·B = 1 if and only if A = 1 and B = 1.
4Logical sum (OR)A+B = 1 if A = 1 or B = 1 (or both).
5PrecedenceParentheses first, then NOT, then AND, then OR. So AB + C means (A·B) + C.

Common mistakeThe standard order is parentheses, NOT, AND, OR. XOR is not a basic operation, so put brackets around it. In Verilog the bitwise order is ~, then &, then ^, then |.

Theorems

NameForm 1 (OR form)Form 2 (AND form, the dual)
IdentityA + 0 = AA · 1 = A
Null elementA + 1 = 1A · 0 = 0
IdempotentA + A = AA · A = A
ComplementA + A' = 1A · A' = 0
Involution(A')' = A(same)
CommutativeA + B = B + AA·B = B·A
Associative(A+B)+C = A+(B+C)(A·B)·C = A·(B·C)
DistributiveA·(B+C) = A·B + A·CA + B·C = (A+B)·(A+C)
AbsorptionA + A·B = AA·(A+B) = A
Combining (minimization)A·B + A·B' = A(A+B)·(A+B') = A
De Morgan(A+B)' = A'·B'(A·B)' = A' + B'
Duality: swap + with · and 0 with 1. If a statement is true, its dual is true.
Example: A + 1 = 1 has the dual A · 0 = 0

Common mistakeDuality and De Morgan are two different results. Duality gives a second true statement from a true one. De Morgan gives the complement of a sum or a product. Learn both. It extends to any number of variables: (A+B+C)' = A'B'C' and (ABC)' = A'+B'+C'.

NoteTwo results that appear in almost every simplification: A + A'B = A + B and the consensus theorem AB + A'C + BC = AB + A'C. All theorems above, and these two, were verified by checking every input combination in code.

NumericalProve A + A'B = A + B.
A + A'B = (A + A')(A + B) by the distributive law = 1·(A + B) by the complement law = A + B by the identity law.

Combinational logic analysis: canonical SOP and POS

DefineNumericalLikely exam

Canonical formA standard way of writing a Boolean function in which every term contains every variable once. Two types: canonical SOP (a sum of minterms) and canonical POS (a product of maxterms).

  • Minterm: an AND (product) term in which each variable appears once, uncomplemented if its bit is 1, complemented if its bit is 0. For n variables there are 2n minterms. A minterm is 1 for exactly one input row.
  • Maxterm: an OR (sum) term in which each variable appears once, uncomplemented if its bit is 0, complemented if its bit is 1. A maxterm is 0 for exactly one input row.

Relation between them: Mi = mi′. Row i of the truth table gives minterm mi (used in SOP when F = 1) and maxterm Mi (used in POS when F = 0).

F = Σm(rows where F = 1) = Π M(rows where F = 0)
The two index lists together contain every number from 0 to 2n − 1
Example (3 variables): Σm(0,2,5) = ΠM(1,3,4,6,7)

Procedure

  • Canonical SOP: make the truth table, pick the rows where F = 1, write one minterm for each, OR them.
  • Canonical POS: make the truth table, pick the rows where F = 0, write one maxterm for each, AND them.

ProblemWorkingAnswer

Common mistakeFor Σm(0,2,7), minterm 2 (010) is A'BC', not A'BC (A'BC is minterm 3). Watch the prime marks when writing minterms.

NoteTo get the complement of a function from its canonical form, take the missing terms: if F = Σm(0,2,7) then F' = Σm(1,3,4,5,6). Writing the complement of a POS needs no algebra: F = ΠM(1,2,5) gives F' = Σm(1,2,5).

Logic minimization: algebraic method

DefineNumericalLikely exam

Logic minimizationReducing a Boolean expression to its simplest form (fewest terms and literals) without changing its truth table.

  • Why: fewer gates, lower hardware cost, faster circuit, less power, fewer delays.
  • Algebraic method: apply the Boolean laws step by step. It needs no tables, but there is no guarantee that you have reached the minimum. K-maps (next section) do give a guarantee for up to four variables.
  • Tricks: group terms that differ in one variable (A·B + A·B' = A), use A + A'B = A + B, use the distributive law of the OR form, and add a repeated term (A = A + A) when you need it.

Worked examples (checked in code)

SimplifyStepsAnswer
F = x'y'z + x'yz + xyx'z(y' + y) + xy. Complement law: y' + y = 1. Identity lawF = x'z + xy
F = (x+y)(x+y')xx + xy' + xy + yy'. Then x + xy' + xy + 0. Then x + x(y' + y). Complement and identity: x + x. Idempotent lawF = x
F = A'B + AB' + ABCombine AB' + AB = A. Then A'B + A. Use A + A'B = A + BF = A + B
F = AB + A'C + BCConsensus theorem: BC is redundantF = AB + A'C

NoteCost of a circuit is usually counted as the number of literals (each appearance of a variable) and the number of terms. A minimal form is not always unique: two different expressions with the same cost can both be minimal.

K-map (Karnaugh map) minimization

DefineDrawNumericalLikely exam

K-mapA graphical method of minimization for 2, 3 or 4 variables. The truth table is redrawn as a grid in which neighbouring cells differ in exactly one variable. Group the 1s to get SOP, or group the 0s to get POS.

Layout

  • 2 variables: 2 × 2 grid (4 cells). 3 variables: 2 × 4 grid (8 cells). 4 variables: 4 × 4 grid (16 cells).
  • Row and column labels use Gray code order: 00, 01, 11, 10 (not binary order), so that adjacent cells differ in one bit.
  • The first and last row, and the first and last column, are also adjacent. The map wraps around like a cylinder. The four corners of a 4-variable map are neighbours.
  • Each cell is one minterm. Its number is the binary value of the variable bits, A as the most significant bit.

Grouping rules

  • Groups contain 1, 2, 4, 8 or 16 cells (a power of 2) and are rectangles (wrap-around allowed). No diagonals.
  • Make each group as large as possible. A larger group removes more variables.
  • Every 1 must be in at least one group. Use as few groups as possible. Groups may overlap.
  • A group of 2k cells removes k variables.

Reading a group

  • SOP (group the 1s): each group gives a product term. Keep a variable if it has the same value in every cell of the group: write it uncomplemented if the value is 1, complemented if 0. Drop variables that change. OR the product terms.
  • POS (group the 0s): first read the groups of 0s the same way to get F' as a SOP, then complement using De Morgan. Equivalently, each group gives a sum term, writing a variable complemented if it is 1 in the group and uncomplemented if 0, and then AND the sum terms.

Example 1: 3 variables, with wrap-around

NumericalMinimize F(A,B,C) = Σm(0,2,4,5,6).

  • Group 1 (cells 0, 2, 4, 6): B and A change, only C stays, and it is 0. Term C'.
  • Group 2 (cells 4, 5): A = 1 and B = 0 stay, C changes. Term AB'.
F = C' + AB'

Example 2: 4 variables, SOP and POS from the same map

NumericalMinimize F(A,B,C,D) = Σm(0,1,2,5,8,9,10) in SOP and in POS.

GroupCellsConstant variablesTerm
Four corners0, 2, 8, 10B = 0, D = 0B'D'
Top and bottom, left two columns0, 1, 8, 9B = 0, C = 0B'C'
Pair1, 5A = 0, C = 0, D = 1A'C'D
SOP: F = B'D' + B'C' + A'C'D (7 literals)

POS from the same map. The 0s are in cells 3, 4, 6, 7, 11, 12, 13, 14, 15. Group them: AB (12, 13, 14, 15), CD (3, 7, 11, 15) and BD' (4, 6, 12, 14). So F' = AB + CD + BD'. Complement with De Morgan:

POS: F = (A' + B')(C' + D')(B' + D) (6 literals)

Both answers are correct and give the same truth table. Which one to write: use SOP when the question says SOP, POS when it says POS. When it does not say, give the one with fewer literals.

NoteAn essential prime implicant is a group that is the only one covering some 1. You must include all of them. In Example 2, A'C'D is essential because cell 5 has no other 1 next to it. After the essential groups, choose the fewest extra groups to cover the remaining 1s. Both Examples 1 and 2 were minimized in code and matched.

Don't care conditions

DefineNumericalLikely exam

Don't careAn input combination that never occurs, or whose output does not matter. It is marked X (or d) in the truth table and on the K-map. You are free to treat each X as 0 or as 1, whichever makes the groups bigger.

  • Group an X only if it makes a group bigger. Do not form a group of X cells alone, and do not worry if some X cells remain uncovered.
  • For POS, an X may also be included in a group of 0s.
  • A common source of don't cares: BCD digits use codes 0000 to 1001, so 1010 to 1111 (10 to 15) never occur.

Example 1: Σm(1,3,7,11,15) + d(0,2,5)

GroupCellsTerm
Top row0, 1, 3, 2A'B'
Column CD = 113, 7, 15, 11CD
SOP: F = A'B' + CD
POS: F = D(A' + C)

Taking 5 as 1 instead gives A'D + CD, which has the same cost. Both are minimal and both are correct for this function.

Example 2: BCD digit is 5 or more

NumericalF is 1 for BCD digits 5, 6, 7, 8, 9 and 0 for 0 to 4. Codes 10 to 15 are don't cares. Minimize.

CaseResult
With don't caresA covers 8 to 15 (8 and 9 are needed, 10 to 15 are free). BC covers 6, 7, 14, 15. BD covers 5, 7, 13, 15. F = A + BC + BD
Without (treating 10 to 15 as 0)F = A'BC + A'BD + AB'C'. Each term has three literals. Longer and slower

NoteIn Verilog, x means "unknown" in simulation. A don't care in a K-map is a design decision you make by hand. Do not write x in the equations you give to assign. Write the final minimized expression. Both results above were found with a minimizer in code and matched.

  • BCD (8421): each decimal digit is its 4-bit binary value. Bit weights 8, 4, 2, 1. Codes 1010 to 1111 are unused.
  • 2421: weights 2, 4, 2, 1. Digits 0 to 4 are 0000 to 0100 and 5 to 9 are 1011 to 1111.
  • Excess-3: BCD plus 3. Not weighted.
  • Self-complementing code: the 9's complement of a digit is found by inverting every bit. Example in 2421: 6 = 1100, invert to 0011 = 3 = 9 − 6. 2421 and excess-3 are self-complementing. BCD 8421 and Gray are not. This was checked for all ten digits in code.

BCD to excess-3 converter

Inputs B3 B2 B1 B0 (a BCD digit), outputs E3 E2 E1 E0. Codes 10 to 15 are don't cares. K-map results (minimizer output, then confirmed by simulating all ten digits):

E3 = B3 + B2B0 + B2B1
E2 = B2'B1 + B2'B0 + B2B1'B0'
E1 = B1'B0' + B1B0 (= XNOR of B1 and B0)
E0 = B0'

Common mistakeTwo points that are often confused. (1) 8421 weights give the same bits as ordinary binary only for a single digit 0 to 9; a multi-digit number differs (983 is 1001 1000 0011 in BCD). (2) Gray code is not self-complementing in the decimal sense: the 9's complement of 0 is 9, but Gray 0000 inverted is 1111, while Gray 9 is 1101. Of the codes listed, only 2421 and excess-3 have that property.

BCD code addition

NumericalDefineLikely exam

BCD additionAdd each pair of BCD digits as 4-bit binary numbers, with the carry from the digit below. If the 4-bit sum is greater than 9 or produces a carry out, add 0110 (6) to that digit. The carry out then moves to the next digit.

  • Why add 6: a 4-bit binary digit has 16 values but BCD uses 10. The six unused codes (1010 to 1111) must be skipped, and adding 6 skips them and also produces the decimal carry.
  • Work from the least significant digit upward.
Correction needed when: K + Z3·Z2 + Z3·Z1 = 1
K is the carry out of the 4-bit binary sum, Z3 Z2 Z1 Z0 is the 4-bit sum

Modeling concurrent functionality: continuous assignment

DefineExplainLikely exam

Continuous assignmentA Verilog statement assign <net> = <expression>; that drives a net continuously. Whenever any signal in the expression changes, the output is recalculated. It models combinational logic.

  • Hardware is concurrent: every gate works at the same time. Every assign statement is one such block, and all of them run at the same time.
  • The left side must be a net (wire), not a reg.
  • The order of the statements does not matter. In the simulation below the statement for z (which uses x and y) is written first, and the result is still correct.
  • It is equivalent to drawing gates in a circuit: the expression is the circuit and the net is its output wire.

Continuous assignment with logical operators

Examples run in a simulator

module sop(input A, B, C, output F);        // F = sum m(0,2,7)
  assign F = (~A & ~B & ~C) | (~A & B & ~C) | (A & B & C);
endmodule

module pos(input A, B, C, output F);        // F = product M(1,2,5)
  assign F = (A | B | ~C) & (A | ~B | C) & (~A | B | ~C);
endmodule

module fa(input a, b, cin, output sum, cout);   // full adder
  assign sum  = a ^ b ^ cin;
  assign cout = (a & b) | (cin & (a ^ b));
endmodule

module conc(input A, B, output x, y, z);   // three concurrent assignments
  assign z = x ^ y;       // written first, still works
  assign y = A | B;
  assign x = A & B;
endmodule

Continuous assignment with the conditional operator

DefineExplainDrawLikely exam

Conditional operatorassign Y = (condition) ? value_if_true : value_if_false; It implements multiplexer (decision) logic. It can be nested to form an if, else-if, else chain.

CircuitCodeBehaviour (simulated)
2:1 multiplexerassign Y = S ? D1 : D0;D0=1, D1=0: S=0 gives Y=1, S=1 gives Y=0
4:1 multiplexerassign Y = S[1] ? (S[0] ? D[3] : D[2]) : (S[0] ? D[1] : D[0]);D=1010: S=00 gives 0, 01 gives 1, 10 gives 0, 11 gives 1 (Y = D[S])
Priority chainassign F = A ? X : B ? Y : Z;X=1, Y=0, Z=1. A=1: F=X=1. A=0,B=1: F=Y=0. A=0,B=0: F=Z=1. A=1,B=1: F=X=1 (A has priority)
  • Reading the priority chain: if A then X, else if B then Y, else Z. The first true condition wins.
  • It stays combinational because every branch has a value. A missing else in an always block (not in assign) is what creates unwanted latches.
  • The select condition is a 1-bit test. For a 4:1 MUX use two selects, or nest two levels as shown.

Example: one-digit BCD adder using the conditional operator

module bcd_add(input [3:0] a, b, input cin, output [3:0] sum, output cout);
  wire [4:0] s = a + b + cin;                    // plain binary sum
  wire [4:0] r = (s > 9) ? s + 5'd6 : s;         // add 6 when above 9
  assign sum  = r[3:0];
  assign cout = r[4];
endmodule

Simulated: 7 + 5 gives cout = 1 and sum = 0010 (12). 9 + 9 gives 1 and 1000 (18). 4 + 3 gives 0 and 0111. All 200 combinations of two digits and a carry matched.

NotePriority conditional: A ? X : B ? Y : Z means if A then X, else if B then Y, else Z. A and B are conditions; X, Y and Z are the values. Conditions are tested left to right.

Continuous assignment with delay

DefineDrawExplainLikely exam

Assignment with delayassign #delay Y = expression; The new value of Y appears after the given delay. It models the propagation delay of real gates.

  • For simulation only. Synthesis tools ignore delays, so they cannot be used to build a delay into hardware. Use it to study steady-circuit timing.
  • The delay in a continuous assignment is an inertial delay: a pulse on the input that is shorter than the delay is swallowed (glitch filtering). The output does not change.
  • Delay units come from `timescale, for example `timescale 1ns/1ps makes #2 equal to 2 ns.
  • Examples: assign #2 Y = A & B; and assign #2 F = S ? A : B;
Time (ns)AY without delayY with #2

NoteDifferent rise and fall delays: assign #(2,3) Y = A; gives a 2 ns delay for a rising output and 3 ns for a falling output. The simulation showed Y rise 2 ns after A rose and fall 3 ns after A fell. The time column in the table above is from the same simulator run, with a 1 ns pulse and a 4 ns pulse.

DifferentiateContinuous assignment (assign): for nets, runs all the time, models combinational logic, can have a delay. Procedural assignment (always): for reg variables, runs when triggered. A continuous assignment cannot drive a reg.

One-page cheat sheet

Revise the night before

Laws

  • Identity, Null, Idempotent, Complement
  • Absorption A+AB = A
  • Combining AB+AB' = A
  • A+A'B = A+B
  • Consensus AB+A'C+BC = AB+A'C
  • De Morgan: (A+B)' = A'B', (AB)' = A'+B'
  • Dual: swap + and ·, 0 and 1

Canonical forms

  • Minterm: AND term, bit 1 = A, bit 0 = A'
  • Maxterm: OR term, bit 0 = A, bit 1 = A'
  • Mi = mi'
  • SOP: rows with F = 1
  • POS: rows with F = 0
  • Σm(0,2,5) = ΠM(1,3,4,6,7)

K-map

  • Gray order 00 01 11 10
  • Groups of 1, 2, 4, 8, 16, with wrap-around
  • Largest groups, fewest groups
  • Group 1s for SOP, 0s for POS
  • Keep variables that stay constant
  • X used only to enlarge groups

Worked answers

  • Σm(0,2,4,5,6) = C' + AB'
  • Σm(0,1,2,5,8,9,10) = B'D' + B'C' + A'C'D = (A'+B')(C'+D')(B'+D)
  • Σm(1,3,7,11,15)+d(0,2,5) = A'B' + CD
  • BCD ≥ 5 = A + BC + BD

Codes

  • Gray: G3 = B3, Gi = Bi+1 ⊕ Bi
  • Binary: B3 = G3, Bi = Bi+1 ⊕ Gi
  • Excess-3 = BCD + 3
  • E0 = B0', E1 = B1 XNOR B0
  • Self-complementing: 2421, excess-3

BCD addition

  • Add as binary
  • If sum > 9 or carry out: add 0110
  • Start from the least significant digit
  • 459 + 367 = 1000 0010 0110

Verilog assign

  • assign wire = expression;
  • Net only, never reg
  • All assigns run concurrently, order does not matter
  • ~ & | ^ ~^ for gates
  • Y = S ? D1 : D0 is a 2:1 MUX
  • A ? X : B ? Y : Z is a priority chain
  • assign #2 inertial delay, simulation only
