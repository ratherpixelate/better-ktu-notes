Memory hierarchy and locality

DefineDraw

CacheA small, fast buffer between the processor and main memory. Old values are removed to make room for new ones.

  • Programmers want unlimited fast memory. The fix is a hierarchy: several levels of different speed and size. The whole address space sits in the largest, slowest level. Smaller, faster levels sit close to the processor.
  • It works because of the principle of locality: a program uses a small part of its address space at any instant.
LocalityMeaningExample
TemporalAn item used now is likely to be used again soon.A loop counter, the instructions of a loop body.
SpatialItems near an item just used are likely to be used soon.Array elements, sequential instructions.

Temporal locality is why we keep recently used blocks. Spatial locality is why a miss fetches a whole block, not one word.

Locality IllustrationIn repetitive string processing (e.g. "MISSISSIPPI"), characters like S, I, and P repeat rapidly (temporal locality). In linear array traversal, adjacent index elements reside within the same fetched block (spatial locality).

Organization of a cache

A cache is an array of S = 2s sets. Each set has E lines (E = associativity). Each line has a valid bit, a tag of t bits, and a data block of B = 2b bytes.

Cache size C = B × E × S (data bytes only)
Number of sets S = C / (B × E)
Address (m bits) = tag (t) | set index (s) | block offset (b), t = m − s − b
  • Block offset picks the byte (or word) inside the block.
  • Set index picks the set.
  • Tag is compared with the tag of every valid line in that set. A match on a valid line is a hit.

Worked example: Set and Word Lookup

NumericalA cache has 512 KB capacity, 4 B words, 64 B blocks, 8-way set associative, 32-bit address. For address 0xABC89984, which set is searched and which word is forwarded on a hit?

Sets = 2^19 / (2^6 × 2^3) = 2^10 = 1024 → index 10 bits
Offset = 6 bits (64 B block), tag = 32 − 10 − 6 = 16 bits
0xABC89984 → low 16 bits 1001 1001 1000 0100
offset = 00 0100 = 4 → byte 4 → word 4/4 = word 1
index = 10 0110 0110 = 614
Answer: set 614, word 1. (0x485669AC → set 422, word 11)

Verified: Both addresses resolve consistently with tag, set index, and offset formulas.

Second example: total bits in a cache

Exam FocusFinding the total capacity of a cache including tag, valid, and status overhead bits is a frequent university examination problem.

32 KB direct mapped, 64 B blocks, 32-bit address, write back
Blocks = 32K / 64 = 512 → index 9, offset 6, tag = 32 − 9 − 6 = 17
Bits per line = 64×8 data + 17 tag + 1 valid + 1 dirty = 531
Total = 512 × 531 = 271,872 bits ≈ 33.2 KB (3.7% overhead over 32 KB)

Block replacement

DifferentiateNumericalKey Concept

On a miss in a full set, one block must go. Direct mapped is easy: there is only one candidate. Set associative and fully associative caches need a policy.

PolicyHow it choosesNotes
RandomAny block in the setNeeds a pseudo-random number generator. Ignores temporal and spatial locality.
FIFOThe block that has been in the longestNeeds a queue: enqueue on fill, dequeue to evict. Ignores reuse.
LRUThe block unused for the longest timeUses temporal locality. Needs a recency stack or counters.
LFUThe block with the lowest reference countA counter per block, incremented on each reference. Storage and compare logic are costly.
OptimalThe block whose next use is farthest in the futureNeeds future knowledge, so it cannot be built. Used as a yardstick.

Replacement Anomalies & Pseudo-LRUTrue LRU tracking requires significant hardware logic as associativity grows beyond 4 ways; modern processors employ pseudo-LRU tree-bit approximations. Additionally, FIFO can exhibit Bélády's anomaly (where increasing cache blocks increases miss count, e.g. reference string 1 2 3 4 1 2 5 1 2 3 4 5 yielding 9 misses on 3 blocks vs 10 on 4 blocks). LRU and Optimal are stack algorithms and never suffer from Bélády's anomaly.

Cache performance: AMAT

NumericalImportantKey Concept
AMAT = Hit time + Miss rate × Miss penalty

Two levels:
AMAT = Hit time(L1) + Miss rate(L1) × [ Hit time(L2) + Miss rate(L2) × Miss penalty(L2) ]
  • Local miss rate = misses in a level / accesses to that level.
  • Global miss rate = misses in a level / accesses generated by the CPU. For L2: global = L1 miss rate × L2 local miss rate.
  • Optimising the cache means lowering AMAT by cutting the miss rate, the miss penalty or the hit time.

Formula Discrepancy NoteCertain examination questions express AMAT as Hit rate × Hit time + Miss rate × Miss latency (e.g. 0.9 × 10ns + 0.1 × 100ns = 19ns). The standard computer architecture formulation (Hennessy & Patterson) is Hit time + Miss rate × Miss penalty (yielding 20ns). Clearly state your formula assumption when solving descriptive numericals.

Numerical 1: Two-level cache performance

NumericalIn 1000 memory references there are 40 misses in L1 and 20 in L2. L2 miss penalty to memory is 200 cycles, L2 hit time 10, L1 hit time 1, and 1.5 memory references per instruction. Find the miss rates, the AMAT and the average stall cycles per instruction (ignore writes).

L1 miss rate = 40/1000 = 4%
L2 local miss rate = 20/40 = 50% L2 global miss rate = 20/1000 = 2%
AMAT = 1 + 0.04 × (10 + 0.5 × 200) = 1 + 0.04 × 110 = 5.4 cycles
Stalls per instruction = 1.5 × (0.04 × 10 + 0.02 × 200) = 1.5 × 4.4 = 6.6 cycles

Stall Cycles ImpactStalls per access = AMAT − L1 hit time = 4.4 cycles. Multiplying by 1.5 accesses per instruction yields 6.6 stall cycles per instruction. Combined with a baseline CPU execution CPI of 1.0, the effective CPI equals 7.6.

Six basic cache optimizations

ExplainImportantKey Concept

Syllabus CoreThe KTU 2024 scheme syllabus targets the canonical six basic cache optimizations (Hennessy & Patterson, Appendix B.3), systematically categorizing techniques to reduce miss rate, miss penalty, and hit time.

#OptimizationReducesDrawback
1Larger block sizeMiss rate (compulsory)Higher miss penalty, more conflict misses, pollution
2Larger cacheMiss rate (capacity)Longer hit time, more cost, area and power
3Higher associativityMiss rate (conflict)Longer hit time, more complex
4Multilevel cachesMiss penaltyMore hardware, more complex analysis
5Read misses before writesMiss penaltyMust check the write buffer for a match
6No address translation when indexingHit timeLimits cache size, or needs extra care

1. Larger block size

  • For: uses spatial locality, cuts compulsory misses.
  • Against: higher miss penalty (more bytes to fetch, bus width limits it), more conflict misses (fewer blocks in the cache), and pollution (useless data may evict useful data).
  • The miss rate against block size curve is U-shaped for a given cache size.

2. Larger cache

  • For: cuts capacity misses, holds a bigger working set.
  • Against: longer hit time, higher cost, area and power. Common in L2 and L3, less in L1.

3. Higher associativity

  • For: cuts conflict misses and the eviction rate. Fully associative is best for miss rate but its hit time is high, so pick a moderate associativity.
  • Against: longer hit time (search the set, compare more tags), more complex than direct mapped. A bigger hit time can outweigh the lower miss rate in AMAT.
  • As far as I know, 8-way is already about as good as fully associative for most programs.

4. Multilevel caches

  • Caches must be fast to keep pace with the processor and large to bridge the gap to memory. One cache cannot be both.
  • L1 is small enough to match the clock cycle (low hit time). L2 is large enough to catch many accesses that would go to memory (low miss rate), so it lowers the effective miss penalty.
  • Use local and global miss rates (see AMAT above). An inclusive cache keeps a copy of everything held in the level above. An exclusive one does not duplicate it.

5. Giving priority to read misses over writes

AddedA read miss stalls the processor. A write usually does not need to, because the data can wait in a write buffer.

  • Put the write in the write buffer and let the read miss go to memory first.
  • Danger: the read may need the value still sitting in the buffer (a RAW hazard through memory). Example for a direct mapped write-through cache where addresses 512 and 1024 map to the same block: SW R3, 512(R0) then LW R1, 1024(R0) then LW R2, 512(R0). R3 must equal R2.
  • Fix: either wait until the buffer drains (slow), or check the write buffer on a read miss and take the data from it if there is a match (usual choice).
  • Write back: copy the dirty victim to a buffer, read the missing block first, then write the victim to memory.

6. Avoiding address translation during cache indexing

AddedA physical cache needs the TLB translation before the lookup, which adds to hit time. Options:

  • Virtual cache: index and tag with virtual addresses, so no translation on a hit. Problems: cache flush or process-ID tags on a context switch, and synonyms (two virtual addresses for the same physical address).
  • Virtually indexed, physically tagged (VIPT): use the page offset (same in virtual and physical addresses) as the index, so the cache lookup and TLB lookup go in parallel. Condition: index + block offset bits ≤ page offset bits.
  • Numerical: 4 KB pages (12 offset bits), 64 B blocks, 8-way. Largest VIPT cache = page size × associativity = 4 KB × 8 = 32 KB (index 6 bits + offset 6 bits = 12).

DRAM, SRAM and DRAM organization

DifferentiateDefineDraw

Main memory is built from DRAM. The controller sits on the processor side and talks to the DRAM banks through a DRAM interface.

SRAMDRAM
Cell6 transistors1 transistor + 1 capacitor
SpeedFaster (no capacitor)Slower (capacitor)
Density, costLower density, higher costHigher density, lower cost
RefreshNot neededNeeded (costs power, performance, circuitry)
ProcessCompatible with the logic processCapacitor and logic made together
Used forCachesMain memory
  • A DRAM bit is a charge on a capacitor. The read is destructive: the cell loses its charge when read, so the sense amplifier regenerates the value. The charge also leaks over time.
  • Refresh: the controller must periodically read every row within the refresh time so that the charge is restored.
  • A DRAM array has 2n rows and 2m columns. The row address (RAS) is applied first, then the column address (CAS). Both use the same address pins.

DRAM Refresh TimingStandard DDR SDRAM mandates refreshing all rows within a 64 ms retention interval. For an 8192-row bank architecture, refresh operations occur every 64 ms / 8192 ≈ 7.8 µs (tREFI). During refresh execution, target banks cannot service active memory requests.

Why a rank?

  • An 8-bit chip is easier to make than a 32-bit or 64-bit chip. So make narrow chips but operate them together as a rank.
  • Slide example: 4 chips × 8 bits = 32 bits in one read. A normal DIMM rank uses 8 chips × 8 bits = 64 bits.
  • Granularity: an access cannot be smaller than the interface width. Flexibility: the controller deals with the rank as one wide chip.

Capacity Sizing16K rows (214) × 2 KB row buffer × 8 banks = 256 MB per chip. Combining 8 chips in a 64-bit rank yields 2 GB total physical capacity.

NumericalTransferring a 64 B cache block over a 64-bit (8 B) bus: 64 / 8 = 8 transfers, so 8 I/O cycles. The rank reads 8 columns one after another from the open row (a burst).

Memory modules, banks and interleaving

ExplainNumericalDifferentiate

Modules and channels

  • A DIMM has chips on both sides. Rank 0 (front) and rank 1 (back) share the 64-bit data bus and are picked with chip-select (CS) lines.
  • Multiple DIMMs on a channel: more capacity, but more interconnect complexity and energy.
  • Multiple channels: each has its own controller and data bus, so more bandwidth, but more wires, area, power and processor pins.

Handling several accesses per cycle

MethodIdeaProblem
True multiportingEach cell has several read/write ports.Expensive in latency, power, area. Same-cell read and write needs special logic.
Virtual multiportingTime-share one port; each access is much shorter than a clock.Not scalable.
Multiple cache copiesStores update all copies, loads proceed in parallel.Stores are a bottleneck; area grows with ports.
Banking (interleaving)Split the address space into banks. Address bits pick the bank.Two accesses to the same bank conflict. Needs a crossbar.

Interleaving

  • A single big array is slow to access and cannot serve accesses in parallel. Divide it into banks that work independently. Each is smaller and faster, and accesses to different banks overlap.
  • Key issue: how data maps to banks. In low-order interleaving, adjacent words go to different banks (bank = word address mod number of banks).
  • Slide example: 13-bit physical address, 2 banks of 1K words, 4-byte words → 2 bits byte-in-word, 1 bit bank, 10 bits row. Even words in bank 0, odd words in bank 1.
  • With 2 banks the word sequence 0, 1, 2, 3, 4, 5 goes to banks 0, 1, 0, 1, 0, 1. A sequential stream keeps both banks busy.

Peak Bandwidth CalculationFor a DDR4-2400 module with a 64-bit (8-byte) channel bus: 2400 MT/s × 8 B = 19.2 GB/s peak throughput. Transferring one 64 B cache line requires 8 burst transfers (4 clock cycles at 1200 MHz = 3.33 ns bus transfer duration).

Multiple banks and channels let the controller overlap accesses: while bank 0 is busy opening a row, bank 1 can serve another request, as long as there are no bank conflicts or channel conflicts. Without banks, every access waits for the previous DRAM access to finish.

DRAM controller architecture

Key ConceptDrawExplain

Controller SubsystemsThe memory controller coordinates front-end memory requests with back-end DRAM timing rules, managing queues, address arbitration, command scheduling, and refresh intervals.

The memory controller sits on the processor chip. It takes cache-miss requests and turns them into legal DRAM commands, in an order that gives good performance while obeying every timing rule.

BlockJob
Request queuesHold pending read and write requests from the cores and caches.
Address mapperSplits the physical address into channel, rank, bank, row and column (see the next section).
Command schedulerPicks which request goes next and converts it into ACT, RD/WR and PRE commands. Applies the row-buffer policy.
Bank state and timing checkerTracks which row is open in each bank and the timing constraints (tRCD, tCL, tRP, tRAS ...). A command is sent only when it is legal.
Refresh engineIssues refresh commands on schedule.
Data buffersHold read data coming back and write data waiting to go out.

Scheduling

  • FCFS: serve in arrival order. Simple, but ignores the row-buffer state.
  • FR-FCFS (first-ready, first-come first-served): serve requests that hit the open row first, then the oldest. This raises the row-hit rate and the throughput. Risk: a stream of hits can starve other requests, so controllers add an age limit.
  • Reads are usually served before writes, since a read stalls the processor. Writes wait in a queue and are sent in batches.
  • On-chip controllers need more pins for more channels. Several cores share the controller, so a fair scheduler also limits interference between applications.

Where do blocks at addresses 0x00, 0x40, 0x80, ... 0x1C0 go? Row interleaving: all eight stay in bank 0, row 0 (one miss, then 7 row hits). Block interleaving: banks 0, 1, 2, ... 7, so all eight accesses can be overlapped.

More tricks from the slides

  • Bank mapping randomization: XOR the bank bits with some other address bits (for example low row bits) so that regular strides spread over banks and bank conflicts are less likely.
  • Multiple channels: a channel bit C is added. Its position decides where consecutive blocks go. Put it just above the block offset and consecutive cache blocks alternate between channels. Put it among the row bits and a large region stays on one channel.
  • Virtual to physical: a 64-bit virtual address has a 52-bit page number and a 12-bit page offset. The physical address here is a 19-bit frame number + 12-bit offset = 31 bits. The OS picks the frame, so it controls the upper bank, channel and row bits. It can use page coloring to minimise bank conflicts and interference between applications.

One-page cheat sheet

Revise the night before

Cache address

  • Address = tag | index | offset
  • Sets = C / (B × E)
  • offset = log2 B, index = log2 sets, tag = rest
  • Total bits per line = data + tag + valid (+ dirty)

Mapping

  • Direct: block mod blocks, 1 compare
  • n-way: block mod sets, n compares
  • Fully: anywhere, no index
  • More ways: fewer conflicts, slower hit

Replacement

  • Random, FIFO, LRU, LFU, Optimal
  • Optimal = farthest next use, a yardstick
  • Trace example: FIFO 15, LRU 12, OPT 9
  • FIFO can show Belady's anomaly

Writes

  • Through: write both. Back: write cache, dirty bit
  • Write allocate (with back), no-write allocate (with through)
  • Look-aside: parallel. Look-through: cache first

Misses

  • Compulsory: first access
  • Capacity: cache too small
  • Conflict: same set overloaded

AMAT

  • Hit time + miss rate × penalty
  • 2-level: H1 + M1 × (H2 + M2 × P2)
  • Local = misses / accesses to that level
  • Global = misses / CPU accesses
  • Stalls/instr = refs/instr × (AMAT − H1)

Six optimizations

  • Larger block, larger cache, higher assoc: miss rate
  • Multilevel, read priority over writes: miss penalty
  • No translation on index (VIPT): hit time
  • VIPT max size = page size × ways

DRAM hierarchy

  • Channel → DIMM → rank → chip → bank → row, column
  • Rank = 8 chips × 8 bits = 64 bits
  • 64 B block = 8 transfers on a 64-bit bus
  • DRAM: 1T1C, refresh. SRAM: 6T, faster

DRAM commands

  • ACT (RAS, tRCD) → RD/WR (CAS, tCL) → PRE (tRP)
  • Hit = tCL
  • Empty = tRCD + tCL
  • Conflict = tRP + tRCD + tCL

Controller

  • Queues, address mapper, scheduler, bank timing, refresh, buffers
  • FR-FCFS: row hits first, then oldest

Address mapping (2 GB)

  • 14 row + 3 bank + 11 col + 3 byte = 31 bits
  • Row interleave: row stays in one bank
  • Block interleave: blocks rotate across banks
  • XOR bank bits, page coloring

Row buffer policy

  • Open: keep row open, good for locality
  • Close: precharge after access, uniform latency
  • Open wins above 50% hit rate (14 / 28 / 42 ns example)
