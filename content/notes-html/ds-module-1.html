Data, information and data structures

DefineShort note

DataA collection of raw facts, figures or symbols that have no meaning by themselves. Data becomes useful only when processed.

InformationProcessed, organised or structured data that has meaning and can be used for decisions.

Data structureA way of organising and storing data in a computer so that it can be accessed and modified efficiently. It defines the logical relationship among data elements and the operations on them.

NoteExample: the numbers 45, 67, 89 are data. "The class average is 67" is information.

Need for data structures

  • Efficient data access.
  • Optimal use of memory.
  • Faster processing.
  • Handling large amounts of data.
  • Better performance of algorithms.
  • Required for complex tasks.

Classification of data structures

DifferentiateDefine3 marks

ADT and CDT

ADTAbstract Data Type. A logical description of how data is viewed and the operations allowed on it, without saying how it is implemented. Users work through the interface. Examples: stack, queue, list, tree, graph.

CDTConcrete Data Type. The actual implementation of an ADT using a specific programming language and memory model, such as arrays, linked lists or pointers. Examples: array-based stack, linked list, doubly linked list, binary tree using pointers, hash table using arrays and a hash function.

ADTCDT
DescribesWhat the data is and what operations existHow the operations are implemented
LevelLogical, high levelPhysical, implementation level
DetailsHides implementation detailsExposes the internal representation
Change of implementationPrograms using it keep workingPrograms using it can break
ExamplesStack, queue, list, tree, graphArray, linked list, pointer-based tree

NoteOne ADT can have several CDTs. The stack ADT (push, pop) can be built on an array or on a linked list. Books differ a little in which structures they call CDTs, but the answer "ADT is the what, CDT is the how" is safe.

Algorithm analysis: space complexity

DefineNumerical

Analysis of algorithmsThe process of determining the time and space an algorithm needs, as a function of input size n.

Space complexityThe amount of memory an algorithm needs, as a function of input size.

Total space = input space + auxiliary space
  • Auxiliary space: the extra memory used during execution. Temporary variables, the recursion stack and extra arrays all count.
  • Input space: the memory the input itself occupies.

NoteAnother way to write it: S(P) = c + SP(n). The constant c is the fixed part (code, simple variables, constants). SP(n) is the variable part that depends on the instance, such as array size or recursion depth.

AlgorithmAuxiliary spaceReason
Finding max in an arrayO(1)One variable for the max and one loop counter
Binary search, iterativeO(1)Just low, high and mid
Recursive factorialO(n)Recursion depth is n, so n stack frames
Merge sortO(n)Needs an extra array for merging
Binary search, recursive O(log n)Recursion depth is log n
Bubble sort O(1)Sorts in place, one temporary variable for swaps

The first row is auxiliary space only. If you count the input array too, finding the max uses O(n) in total. Say which one you mean.

Asymptotic notations: best, worst, average case

DefineNumericalLikely long answer

Asymptotic notation describes the efficiency of an algorithm when the input size becomes very large. It gives a mathematical expression for time complexity without getting into machine or language details.

NotationCaseGivesMeaning
Ω (Omega)Best caseLower boundMinimum time taken for input size n. The algorithm will not run faster than this for any input
O (Big O)Worst caseUpper boundMaximum time taken for input size n. The algorithm will not run slower than this
Θ (Theta)Average caseTight boundBounded above and below. Describes the expected running time

Formal definitions

O(g(n)) = { f(n) : there exist positive constants c and n₀ such that 0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀ }
Ω(g(n)) = { f(n) : there exist positive constants c and n₀ such that 0 ≤ c·g(n) ≤ f(n) for all n ≥ n₀ }
Θ(g(n)) = { f(n) : there exist positive constants c₁, c₂ and n₀ such that 0 ≤ c₁·g(n) ≤ f(n) ≤ c₂·g(n) for all n ≥ n₀ }

g(n) is an asymptotic upper bound (O), lower bound (Ω) or tight bound (Θ) for f(n).

Worked example

NoteShow that f(n) = 3n + 2 is Θ(n).

Upper bound: 3n + 2 ≤ 4n for all n ≥ 2, so c = 4 and n₀ = 2. Hence f(n) is O(n).

Lower bound: 3n ≤ 3n + 2 for all n ≥ 1, so c = 3 and n₀ = 1. Hence f(n) is Ω(n).

Both hold, so f(n) is Θ(n) with c₁ = 3, c₂ = 4, n₀ = 2.

Another: 2n² + 3n + 1 ≤ 6n² for n ≥ 1 (at n = 1 both sides are 6), so it is O(n²).

Cases for linear search and binary search

AlgorithmBest case, ΩWorst case, OAverage case, Θ
Linear searchKey at first position: Ω(1)Key at last position or absent: O(n)About n/2 comparisons: Θ(n)
Binary search Key at the middle: Ω(1)Halve until one element is left: O(log n)Θ(log n)

Common mistakeStrictly, O, Ω and Θ are bounds on a function, not names for cases. Any of them can describe the best, worst or average case.

Arrays and address calculation

NumericalDefineLikely long answer

ArrayA collection of elements of the same type, stored in contiguous memory locations and accessed by an index.

Properties

  • Fixed size.
  • Homogeneous elements (all the same type).
  • Stored contiguously.
  • Direct access using the index.
  • Static memory allocation.
  • Easy to traverse.
  • Efficient for searching and sorting.

NoteDrawbacks to mention: the size can't change after declaration, and inserting or deleting in the middle means shifting elements, which is O(n).

One-dimensional array in memory

int A[5] = {10, 20, 30, 40, 50}; with base address BA = 2000 and element size w = 4 bytes.

10A[0] · 2000
20A[1] · 2004
30A[2] · 2008
40A[3] · 2012
50A[4] · 2016
Address(A[i]) = BA + i × w (index starts at 0)

A[3] = 2000 + 3 × 4 = 2012.

NoteIf the lower bound is LB instead of 0 (say A[−5…10]): Address(A[i]) = BA + (i − LB) × w. Example: BA = 500, w = 2, LB = −5, then A[2] = 500 + (2 + 5) × 2 = 514.

Two-dimensional array: row-major and column-major

int B[3][3] = {{1,2,3},{4,5,6},{7,8,9}}; is stored as a single run of memory in one of two orders.

OrderUsed byHow it is storedMemory sequence for B
Row-majorC, C++, JavaRow by row1 2 3 4 5 6 7 8 9
Column-majorFortran, MATLABColumn by column1 4 7 2 5 8 3 6 9

For an array A[m][n] with element size w and zero-based indices:

Row-major: Address(A[i][j]) = BA + (i × n + j) × w
Column-major: Address(A[i][j]) = BA + (j × m + i) × w

Here m is the number of rows and n the number of columns. Row-major multiplies the row index by the number of columns. Column-major multiplies the column index by the number of rows.

NoteWorked examples

B[3][3], BA = 1000, w = 4, element B[1][2] (the value 6).

Row-major: 1000 + (1 × 3 + 2) × 4 = 1020. Column-major: 1000 + (2 × 3 + 1) × 4 = 1028.

A[10][10], BA = 2000, w = 2, element A[3][4].

Row-major: 2000 + (3 × 10 + 4) × 2 = 2068. Column-major: 2000 + (4 × 10 + 3) × 2 = 2086.

NoteWith lower bounds. For A[l₁…u₁][l₂…u₂] let rows = u₁ − l₁ + 1 and cols = u₂ − l₂ + 1.

Row-major: BA + ((i − l₁) × cols + (j − l₂)) × w
Column-major: BA + ((j − l₂) × rows + (i − l₁)) × w

Example: A[1…5][1…4], BA = 100, w = 2, element A[3][2]. rows = 5, cols = 4.

Row-major: 100 + ((3 − 1) × 4 + (2 − 1)) × 2 = 118. Column-major: 100 + ((2 − 1) × 5 + (3 − 1)) × 2 = 114.

Sparse matrix

DefineNumericalLikely long answer

Sparse matrixA matrix in which most elements are zero, so the number of zero values is much greater than the number of non-zero values. Storing every zero wastes memory.

Triplet representation

Store only the non-zero elements. Each one is a row of three values: (row, column, value). The first row of the table is a summary: number of rows, number of columns, number of non-zero values.

Example: a 6 × 6 matrix with 5 non-zero values.

NoteSpace saving. The full matrix needs m × n cells. The triplet form needs 3 × (t + 1) cells for t non-zero values. Here that is 36 against 3 × 6 = 18. The triplet form wins when 3(t + 1) < m × n.

Linked list representation

Each non-zero element is a node holding row | column | value | next. A pointer first points to the first node, and the nodes are linked in row order.

first → [0|4|9] → [1|1|8] → [2|0|4] → [3|3|2] → [5|5|5] → NULL

Unlike the triplet array, nodes can be added or removed without shifting. The cost is an extra pointer per element.

Polynomial representation and addition

A polynomial is a sum of terms, each with a coefficient and an exponent. Store it in a two-column array: column 0 holds the coefficient, column 1 the exponent. Keep the terms in descending order of exponent.

A[i][0] is the coefficient of term i. A[i][1] is its exponent.

Algorithm for polynomial addition

Add polynomial A (n1 terms) and polynomial B (n2 terms) into C. It works like merging two sorted lists.

  1. Start.
  2. Declare integer arrays A[n1][2], B[n2][2] and C[n1 + n2][2].
  3. Read the terms of the first polynomial into A and the second into B, using for loops.
  4. Set i to 0, j to 0 and k to 0.
  5. Repeat steps 6 to 8 while i is less than n1 and j is less than n2.
  6. If A[i][1] is greater than B[j][1], copy A[i][0] and A[i][1] into C[k][0] and C[k][1], then increase i and k by 1.
  7. Else if A[i][1] is less than B[j][1], copy B[j][0] and B[j][1] into C[k][0] and C[k][1], then increase j and k by 1.
  8. Otherwise the exponents are equal. Set sum to A[i][0] + B[j][0]. If sum is not equal to 0, set C[k][0] to sum and C[k][1] to A[i][1], and increase k by 1. Increase i and j by 1.
  9. While i is less than n1, copy A[i] into C[k], then increase i and k by 1.
  10. While j is less than n2, copy B[j] into C[k], then increase j and k by 1.
  11. If k is equal to 0, print 0. Otherwise, for x from 0 to k − 1, print C[x][0] followed by x^C[x][1] (leave out the x part when the exponent is 0), and print + between terms.
  12. Stop.

Worked example

NoteA = 5x³ + 3x + 2 and B = 4x³ + 2x² − 3x + 6.

Stack using an array

AlgorithmDefineLikely long answer

StackA linear data structure stored in contiguous memory in which items are added and removed at one end only, called the top. It follows LIFO (last in, first out).

  • Push: insertion. Pop: deletion.
  • Overflow: push on a full stack, when top reaches the maximum.
  • Underflow: pop on an empty stack, when top reaches the minimum.
top = −1 means the stack is empty.
top = MAX − 1 means the stack is full. (array a[0 … MAX−1])

Common mistakeThat works only if the array is declared with MAX + 1 cells. With an array of MAX cells indexed 0 to MAX − 1, the test is top = MAX − 1. State the convention at the top of your answer.

Push (a, top, item, MAX)

  1. Start.
  2. If top is equal to MAX − 1, print "Stack Overflow" and stop.
  3. Increase top by 1.
  4. Assign item to a[top].
  5. Stop.

Pop (a, top)

  1. Start.
  2. If top is equal to −1, print "Stack Underflow" and stop.
  3. Assign a[top] to item.
  4. Decrease top by 1.
  5. Print item as the deleted element.
  6. Stop.

Display (a, top)

  1. Start.
  2. If top is equal to −1, print "Stack is empty" and stop.
  3. For i from top down to 0, print a[i].
  4. Stop.

Push and pop are O(1). Display visits every element, so it is O(n).

Applications

  • Reversing a string.
  • Checking that nested parentheses in an expression are balanced.
  • Converting infix to postfix and evaluating postfix (the next two sections).
  • Undo and redo operations.
  • Browser history navigation.
  • Function call stack during recursion

Queue using an array

AlgorithmDefineDifferentiate

QueueA linear data structure that allows insertion at one end (rear) and deletion at the other end (front). It follows FIFO (first in, first out).

  • A queue uses two pointers, FRONT and REAR. A stack uses only one, TOP.
  • Insertion is enqueue, deletion is dequeue.
  • Start with FRONT = −1 and REAR = −1 (empty queue).

Enqueue (Q, MAX, num)

  1. Start.
  2. If REAR is equal to MAX − 1, print "Queue Overflow" and stop.
  3. If FRONT is equal to −1, set FRONT to 0.
  4. Increase REAR by 1.
  5. Assign num to Q[REAR].
  6. Stop.

Dequeue (Q)

  1. Start.
  2. If FRONT is equal to −1, print "Queue Underflow" and stop.
  3. Assign Q[FRONT] to num and print it as the deleted item.
  4. Increase FRONT by 1.
  5. If FRONT is greater than REAR, set FRONT and REAR to −1.
  6. Stop.

Display (Q)

  1. Start.
  2. If FRONT is equal to −1, print "Queue is empty" and stop.
  3. For i from FRONT to REAR, print Q[i].
  4. Stop.

The problem with a linear queue: false overflow

NoteMAX = 5. Enqueue 10, 20, 30, 40, 50, then dequeue twice.

freeQ[0]
freeQ[1]

40Q[3]

REAR is MAX − 1, so enqueue prints overflow, yet two cells at the start are empty. The space freed by dequeues is never reused. A circular queue fixes this.

Circular queue

AlgorithmDifferentiateLikely long answer

Circular queueA queue in which the last position is connected back to the first position, forming a circle. It uses all the array positions efficiently. Need: it prevents false overflow.

The indexes wrap around with the modulo operator: REAR = (REAR + 1) % MAX and FRONT = (FRONT + 1) % MAX.

Full: (REAR + 1) % MAX == FRONT
Empty: FRONT == −1

Common mistakeThe correct overflow test is (REAR + 1) % MAX == FRONT. The test FRONT == 0 and REAR == MAX − 1 is the same situation, and the single modulo test already covers it.

Enqueue (Q, MAX, item)

  1. Start.
  2. If (REAR + 1) % MAX is equal to FRONT, print "Circular Queue Overflow" and stop.
  3. If FRONT is equal to −1, set FRONT to 0.
  4. Set REAR to (REAR + 1) % MAX.
  5. Assign item to Q[REAR].
  6. Stop.

Dequeue (Q, MAX)

  1. Start.
  2. If FRONT is equal to −1, print "Circular Queue Underflow" and stop.
  3. Assign Q[FRONT] to item and print it as the deleted item.
  4. If FRONT is equal to REAR, set FRONT and REAR to −1.
  5. Else set FRONT to (FRONT + 1) % MAX.
  6. Stop.

Display (Q, MAX)

  1. Start.
  2. If FRONT is equal to −1, print "Queue is empty" and stop.
  3. Set i to FRONT.
  4. Repeat: print Q[i]. If i is equal to REAR, stop the loop. Otherwise set i to (i + 1) % MAX.
  5. Stop.

Other queues: deque and priority queue

DefineConcept only3 marks

Deque (double-ended queue)

DequeA queue in which insertion and deletion can both be done at either end, front or rear. Four operations: insert at front, insert at rear, delete from front, delete from rear.

TypeInsertionDeletion
Input-restricted dequeAt one end onlyAt both ends
Output-restricted dequeAt both endsAt one end only

Application: palindrome checker. Insert the characters, then compare the front and rear characters, removing one from each end per step. If they always match, it is a palindrome.

Priority queue (concept only)

Priority queueA queue in which each element has a priority. Insertion is done in order of arrival, and deletion is based on priority. If two elements have equal priority, they follow FIFO.

TypeRule
Ascending priority queueElements can be inserted in any order, but only the smallest can be removed
Descending priority queueElements can be inserted in any order, but only the largest can be removed

Applications: job scheduling in an operating system, bandwidth management, network communication.

NoteA priority queue is usually implemented with a binary heap, which gives O(log n) insert and delete. The heap algorithms are not needed, since the syllabus asks for the concept only.

Precedence and associativity

OperatorPrecedenceAssociativity

* / %MiddleLeft to right
+ −LowestLeft to right
( on the stackLowest of all, so it never gets popped by an operatornone

Algorithm

  1. Start.
  2. Create an empty stack for operators and an empty output string.
  3. Scan the infix expression from left to right, one token at a time. Repeat steps 4 to 8 for each token.
  4. If the token is an operand, append it to the output.
  5. If the token is an opening bracket, push it onto the stack.
  6. If the token is a closing bracket, pop operators from the stack and append them to the output until an opening bracket is on top. Pop and discard the opening bracket.
  7. If the token is an operator, then while the stack is not empty and the top is not an opening bracket and the top has higher precedence than the token (or equal precedence and the token is left-associative), pop the top and append it to the output.
  8. After that loop, push the token onto the stack.
  9. After all tokens are scanned, pop every remaining operator from the stack and append it to the output.
  10. Print the output as the postfix expression.
  11. Stop.

Postfix evaluation using a stack

NumericalAlgorithmVery likely
  1. Start.
  2. Create an empty stack for operands.
  3. Scan the postfix expression from left to right, one token at a time. Repeat steps 4 to 6 for each token.
  4. If the token is an operand, push it onto the stack.
  5. If the token is an operator, pop the top element into op2, then pop the next element into op1.
  6. Compute the result as op1 operator op2 and push the result onto the stack.
  7. After all tokens are scanned, pop the top element. It is the value of the expression.
  8. Stop.

Common mistakeThe first pop is the right operand. For − and / the order matters: 12 4 / means 12 ÷ 4, so op1 = 12 and op2 = 4. Swapping them is the most common mistake in this question.

Example: 5 6 2 + * 12 4 / −

One-page cheat sheet

Revise the night before

Growth order

  • 1 < log n < n < n log n < n² < n³ < 2ⁿ
  • Drop constants and lower-order terms

Notations

  • O: f ≤ c·g, worst case, upper bound
  • Ω: c·g ≤ f, best case, lower bound
  • Θ: c₁·g ≤ f ≤ c₂·g, average case, tight bound

Space

  • Total = input + auxiliary
  • Recursive factorial O(n), merge sort O(n)
  • Iterative binary search O(1)

Array addresses

  • 1D: BA + i·w
  • Row-major: BA + (i·n + j)·w
  • Column-major: BA + (j·m + i)·w
  • m rows, n columns, zero-based

Sparse and polynomial

  • Triplet: (row, col, value), summary row first
  • Triplet wins when 3(t + 1) < m·n
  • Polynomial: A[i][0] coefficient, A[i][1] exponent, descending

Stack (LIFO)

  • Empty: top = −1. Full: top = MAX − 1
  • Push: top++, then a[top] = item
  • Pop: item = a[top], then top−−

Queue (FIFO)

  • Linear full: REAR = MAX − 1
  • Circular full: (REAR + 1) % MAX = FRONT
  • Empty: FRONT = −1
  • Last dequeue: FRONT = REAR = −1

Deque, priority queue

  • Input-restricted: insert at one end
  • Output-restricted: delete at one end
  • Priority queue: delete by priority, ties are FIFO

Postfix rules

  • Precedence: ^ then * / % then + −
  • Pop while top ≥ token (left-assoc), top > token for ^
  • Evaluate: first pop is op2, second is op1

Likely questions with answer outlines

Covers every syllabus line
Differentiate ADT and CDT. Give two examples each. (3)

ADT is a logical description of data and its operations, with the implementation hidden. CDT is the actual implementation in a language and memory model. Use the table in Classification. ADT examples: stack, queue. CDT examples: linked list, array-based stack.

Compare linear and non-linear data structures. (3)

Sequential single-level and contiguous against hierarchical, multi-level and non-contiguous. Examples: array, linked list, stack, queue against tree, graph. See Classification.

Define space complexity and time complexity. Find the space complexity of recursive factorial. (3)

Space: memory needed as a function of n, which is input plus auxiliary space. Time: how running time grows with n, independent of language and machine. Recursive factorial has depth n, so n stack frames, O(n) space. See Space.

Explain Big O, Omega and Theta with definitions and an example. (7)

Give the three formal definitions with c and n₀, the mapping worst/best/average, and the proof for 3n + 2. Finish with linear search: Ω(1), O(n), Θ(n). See Asymptotic notations.

Draw the growth of n, n², n³, log n and 2ⁿ and tabulate values. (3 or 7)

Draw the five curves on one axes and give the table for n = 1, 2, 4, 8, 16. State the order 1 < log n < n < n² < n³ < 2ⁿ. See Time complexity.

Derive the address of A[i][j] in row-major and column-major order. Find the address of A[3][4] for A[10][10], BA = 2000, w = 2. (7)

Row-major BA + (i·n + j)·w = 2068. Column-major BA + (j·m + i)·w = 2086. See Arrays.

What is a sparse matrix? Represent a given matrix in triplet form. (3 or 7)

Define it, write the summary row (rows, columns, non-zero count), then one row per non-zero value in row order. Mention the space saving condition. See Sparse matrix.

Write an algorithm to add two polynomials using arrays. Add 5x³ + 3x + 2 and 4x³ + 2x² − 3x + 6. (7)

Two-column array representation, then the merge algorithm. Answer: 9x³ + 2x² + 8. See Polynomial addition.

Write algorithms for push, pop and display on an array stack. State overflow and underflow. (7)

Overflow: top = MAX − 1. Underflow: top = −1. See Stack.

Why is a circular queue needed? Write the enqueue and dequeue algorithms. (7)

Linear queue gives false overflow because freed space at the front is never reused. Circular uses the modulo wrap. Full: (REAR + 1) % MAX = FRONT. See Circular queue.

Write a short note on deque and priority queue. (3)

Deque: insertion and deletion at both ends, with input-restricted and output-restricted types. Priority queue: deletion by priority, ties by FIFO, ascending and descending types. See Other queues.

Convert A * (B + C) − D / E to postfix using a stack and evaluate it for A = 2, B = 3, C = 4, D = 8, E = 2. (7)

Postfix ABC+*DE/−. Value 10. See Infix to postfix and Postfix evaluation.

List five applications of a stack. (3)

Reversing a string, balanced parentheses, expression conversion and evaluation, undo/redo, browser history. See Stack.
