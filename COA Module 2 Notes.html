Single-cycle processor

AddedDefineNumerical

AddedYour slides don't cover single-cycle or multi-cycle processors. This section and the next are from the textbook.

Single-cycle processorA processor in which every instruction is fetched, executed and completed in one clock cycle. CPI is 1, and the clock period must fit the slowest instruction, which is the load.

  • All five steps happen inside one cycle: fetch, register read, ALU operation, memory access, register write.
  • No unit can be reused inside a cycle, so the design needs a separate instruction memory and data memory, and separate adders for PC + 4, the branch target and the ALU.
  • Simple to design and CPI is exactly 1.
  • Slow: even a short instruction such as a branch gets the full clock period of the slowest one.

Clock period = longest path = 800 ps, so every instruction takes 800 ps, including the 500 ps branch. If your question gives different delays, use the same method: add the stages each instruction uses and take the largest.

Multi-cycle processor

AddedDifferentiateNumericalCheck

Multi-cycle processorA processor that breaks each instruction into steps and does one step per clock cycle. The clock period fits the longest step, and different instructions take different numbers of cycles.

  • Hardware is reused across cycles: one memory for instructions and data, one ALU for arithmetic, PC + 4 and branch targets.
  • Values needed in the next step are held in intermediate registers (instruction register, memory data register, registers A and B for the operands, ALUOut).
  • The control unit is a finite-state machine that moves from step to step.
  • CPI is greater than 1 and depends on the instruction mix.

Introduction to pipelining

DefineShort noteNumerical

PipeliningAn implementation technique in which the execution of several instructions is overlapped. The work is split into stages, and each instruction is in a different stage at the same time, like an assembly line. Work starts as soon as possible instead of waiting for the previous task to finish completely.

Pipelining partitions the system into multiple independent stages with buffers (registers) between the stages. The performance gain depends on the depth of the pipeline, and it increases the throughput of the system.

Laundry analogy from your slides

Each load needs washing (30 min), drying (40 min) and folding (20 min), so one load takes 90 minutes.

UnpipelinedPipelined
RuleStart a load only when the previous one is completely doneStart work as soon as possible
4 loads4 × 90 = 360 min = 6 hours30 + 4 × 40 + 20 = 210 min = 3.5 hours

AddedThe speedup is 360 / 210 = 1.71, not 3 (the number of stages). The slowest stage (drying, 40 min) sets the rate, and the first load still has to fill the pipe. With very many loads the speedup approaches 90 / 40 = 2.25.

Pipelining characteristics

  • Pipelining does not reduce the latency of a single task. It improves the throughput of the entire workload.
  • The pipeline rate is limited by the slowest pipeline stage.
  • Potential speedup = number of pipe stages.
  • Unbalanced stage lengths reduce the speedup.
  • The time to fill the pipeline and the time to drain it reduce the speedup.

Pipelining issues: ideal case against reality

Ideal caseRealityImpact on the ISA

The five-stage RISC pipeline

DrawExplain stepsLikely long answer

MIPS stands for Microprocessor without Interlocked Pipelined Stages: 32 registers of 32 bits, uniform-length instructions and a load-store architecture. Each instruction takes at most 5 clock cycles, one per stage.

StageNameWhat happens
IFInstruction fetchUse the PC to fetch the instruction from memory. Update the PC to PC + 4.
IDInstruction decode and register fetchDecode the instruction and read the registers. Fixed-field decoding: the register fields are in the same bit positions in every format, so the registers can be read while decoding. In the branch-optimised pipeline, also compare the two registers for equality and compute the branch target.
EXExecute or effective addressMemory reference: effective address = base register + offset, e.g. lw x1, 8(x2) gives [x2] + 8. Register-register ALU operation, e.g. add x1, x2, x3. Register-immediate ALU operation.
MEMMemory accessLoad: read memory at the effective address. Store: write the register data to memory, e.g. sw x3, 16(x4).
WBWrite-backWrite the result into the register file. Used by register-register ALU instructions and loads.
  • Loads and ALU instructions use all five stages. Stores have no write-back, and branches have no memory access or write-back.
  • Your slide lists the unpipelined cycle counts as branch 4, store 4, others 5. See the Check in the multi-cycle section.

Pipelined datapath

The pipelined datapath is the single-cycle datapath cut into five stages, with a pipeline register between each pair of stages. The registers are named after the stages they sit between: IF/ID, ID/EX, EX/MEM, MEM/WB. They hold the instruction's data and control signals, so each stage can work on a different instruction in the same cycle.

Pipeline performance

AddedNumericalVery likely

AddedYour slides say speedup is limited by the number of stages but give no formulas. These are the ones a numerical needs.

Ideal pipeline

A pipeline of k stages with equal stage times runs n instructions in k + n − 1 cycles. Without pipelining the same work takes n × k cycles.

Time (pipelined) = (k + n − 1) × cycle time
Speedup = n·k / (k + n − 1) → k as n becomes large
k = 5, n =151001000
Speedup1.002.784.814.98

One instruction gets no speedup. The speedup approaches the number of stages only for long runs, which is the fill and drain effect.

Unbalanced stages

The clock period must fit the slowest stage. Using the delays from the single-cycle section, the stages are 200, 100, 200, 200, 100 ps, so the pipelined clock is 200 ps and the single-cycle clock is 800 ps.

AddedThree lw instructions: single-cycle 3 × 800 = 2400 ps. Pipelined (5 + 3 − 1) × 200 = 1400 ps.

1000 instructions: single-cycle 800,000 ps. Pipelined (5 + 999) × 200 = 200,800 ps. Speedup = 3.98, about 4, not 5, because the stage times are unequal.

Performance with stalls

CPI (pipelined) = 1 + stall cycles per instruction
Speedup = pipeline depth / (1 + stall cycles per instruction)

The second formula assumes the clock is the same and the unpipelined CPI equals the pipeline depth. More generally, speedup = (CPIunpipelined × clockunpipelined) / (CPIpipelined × clockpipelined).

AddedWorked example. 5-stage pipeline, 20% branches, 25% loads, 30% of loads followed immediately by a dependent instruction (1 stall).

Load-use stalls per instruction = 0.25 × 0.30 × 1 = 0.075.

Branch decision in MEM (3-cycle penalty): stalls = 0.20 × 3 = 0.6, CPI = 1 + 0.6 + 0.075 = 1.675, speedup = 5 / 1.675 = 2.99.

Branch decision in ID (1-cycle penalty): CPI = 1 + 0.2 + 0.075 = 1.275, speedup = 5 / 1.275 = 3.92.

Hazards, and the clock overhead of the pipeline registers, are what keep a real pipeline from reaching its ideal speedup.

Pipeline hazards and structural hazards

Define3 marks

HazardA circumstance that would cause incorrect execution if the next instruction were fetched and executed in its normal clock cycle. Hazards limit pipelining and force stalls.

TypeCause
StructuralAttempting to use the same hardware for two different things at the same time
DataAn instruction depends on the result of a prior instruction still in the pipeline
ControlDelay between fetching an instruction and the decision about a change in control flow (a branch)

Structural hazard example: a single memory port

With one (uniport) memory used for both instructions and data, a load reads data in its MEM stage, in the same cycle that a later instruction needs the memory for its fetch.

Resolving structural hazards

  • Solution 1: wait. The hardware must detect the hazard and have a mechanism to stall. The stalled instruction leaves a bubble in the pipeline.
  • Solution 2: duplicate the hardware so both instructions can progress. The usual design fix is a separate instruction cache and data cache, which removes the memory conflict.

AddedOther causes of structural hazards: a functional unit that is not fully pipelined (the divider in the multicycle section) and a register file with too few write ports.

Cost example. If 40% of instructions access data and each causes one stall on a single-memory machine, CPI = 1 + 0.4 = 1.4. The machine with separate instruction and data memories is 1.4 times faster, other things equal.

Operand forwarding (bypassing)

The result is already computed at the end of EX, so instead of waiting for write-back, forward it from the pipeline register straight to the ALU input of the next instruction.

Hardware change: a multiplexer in front of each ALU input, with extra paths from the EX/MEM and MEM/WB registers, and logic that compares register numbers to select them.

Data hazard even with forwarding: load-use

A load gets its data only at the end of MEM. If the very next instruction needs it in EX, the data is not ready yet, so one stall is unavoidable. The hardware inserts a bubble, then forwards.

AddedA load followed by a store of the loaded value needs no stall. The store only needs the data in MEM, so it is forwarded there.

Control hazards

NumericalExplainCheckVery likely

Control hazardCaused by the delay between fetching a branch and knowing whether it is taken and where it goes. Until then the pipeline does not know which instruction to fetch next.

Conventional pipeline: branch decided in the 4th stage

If the branch outcome is known only after MEM, the three instructions fetched behind it may be on the wrong path. Your slide's example: 10: beq r1,r3,36 is followed by instructions at 14, 18 and 22, and the target at 36 is only fetched afterwards.

Branch-optimised pipeline: branch decided in the 2nd stage

Move the register comparison (equality check, zero test) and the target-address adder into ID. The decision is then known one cycle after the fetch.

Four branch hazard alternatives

#MethodHow it worksPenalty (decision in ID)
1Stall until the branch direction is clearFreeze or bubble the pipeline after the branch1 cycle, always
2Predict not takenKeep fetching the sequential successors. If the branch is taken, squash (flush) them0 if not taken, 1 if taken
3Predict takenStart fetching from the target. But the target address is not known in IF. It is known at the same time as the outcome, in IDStill 1 cycle, so no gain in this pipeline
4Delayed branchThe branch takes effect after one more instruction, the instruction in the branch delay slot, which always executes. One slot is enough for the 5-stage pipeline (MIPS uses this)0 if the slot is filled with useful work

Branch penalty and CPI

Stall always: CPI = 1 + (branch frequency × penalty)
Predict not taken: CPI = 1 + (branch frequency × fraction taken × penalty)

Added20% branches. Decision in MEM, stall always: CPI = 1 + 0.2 × 3 = 1.6. Decision in ID, stall always: 1 + 0.2 × 1 = 1.2.

Dynamic prediction (short)

  • A branch prediction buffer is a small table indexed by the lower bits of the branch address and holds the recent outcome.
  • 1-bit predictor: flips its bit on every misprediction. For a loop branch it mispredicts twice per execution of the loop.
  • 2-bit saturating counter: must mispredict twice in a row before the prediction changes, so a loop branch mispredicts only once per loop.

Pipelining implementation

AddedExplainLikely long answer

AddedYour slides show the pipelined datapath and the forwarding hardware only as pictures. This section writes out what is inside them, using the standard RISC-V textbook version.

What each pipeline register holds

RegisterHolds
IF/IDThe fetched instruction and PC + 4 (or the PC)
ID/EXThe two register values read, the sign-extended immediate, the register numbers (rs1, rs2, rd), the PC, and the control signals for EX, MEM and WB
EX/MEMThe ALU result, the data to store (second register value), the destination register number rd, the zero flag or branch decision, and the control signals for MEM and WB
MEM/WBThe data read from memory, the ALU result, rd, and the control signals for WB

Control signals travel with the instruction

The control unit decodes the instruction once, in ID. The signals are carried down the pipeline through the registers and dropped off in the stage that uses them.

Used inSignals
EXALU source (register or immediate), ALU operation
MEMBranch, memory read, memory write
WBRegister write, memory-to-register (choose memory data or ALU result)

The register file is written in the first half of a clock cycle and read in the second half, so an instruction reading a register in the same cycle another writes it sees the new value. This is why the distance-3 case needs no stall.

Forwarding unit

It compares the source registers of the instruction in EX with the destination registers held in EX/MEM and MEM/WB, and controls the multiplexers at the ALU inputs.

  1. EX hazard. If EX/MEM.RegWrite is 1 and EX/MEM.rd is not x0 and EX/MEM.rd equals ID/EX.rs1, forward the EX/MEM ALU result to the first ALU input (ForwardA = 10). Do the same for rs2 and the second ALU input (ForwardB = 10).
  2. MEM hazard. If MEM/WB.RegWrite is 1 and MEM/WB.rd is not x0 and MEM/WB.rd equals ID/EX.rs1, and the EX hazard did not already apply, forward the MEM/WB value to the first ALU input (ForwardA = 01). Do the same for rs2.
  3. If neither applies, the ALU uses the value read from the register file (select 00).

The EX hazard has priority because it holds the more recent result. The test "rd is not x0" is there because x0 is always 0 and must never be forwarded.

Hazard detection unit (load-use stall)

  1. Check the instruction in ID/EX and the instruction in IF/ID.
  2. If ID/EX.MemRead is 1 (it is a load) and ID/EX.rd equals IF/ID.rs1 or IF/ID.rs2, a stall is needed.
  3. Stop the PC and the IF/ID register from changing, so the same instruction is fetched and decoded again.
  4. Set the control signals going into ID/EX to 0, which turns the instruction in ID into a bubble (a no-op).
  5. After one cycle the load is in MEM and the dependent instruction proceeds, taking the data by forwarding.

Branches

In the branch-optimised pipeline, ID holds an equality comparator and the branch-target adder. When a branch is taken, the instruction in IF/ID is flushed (turned into a bubble) and the PC is loaded with the target, a 1-cycle penalty.

RISC-V integer pipeline with multicycle operations

AddedDefineNumericalLikely long answer

AddedThis syllabus line is not in your slides. It follows Hennessy and Patterson, Appendix C, "extending the pipeline to handle multicycle operations". The latency numbers are the textbook model, not a real chip.

Floating-point operations and divides cannot finish in one EX cycle. Making the clock slow enough for them would slow every instruction, so the EX stage is allowed to take several cycles for these operations. Integer instructions still use the normal one-cycle EX.

Functional units

  • Integer unit: the normal one-cycle EX stage, for integer ALU operations, loads, stores and branches.
  • FP and integer multiplier: pipelined, seven stages M1 to M7.
  • FP adder: pipelined, four stages A1 to A4.
  • FP and integer divider: not pipelined, so it is busy for the whole operation.

After the execution unit, every instruction goes through MEM and WB as usual.

LatencyThe number of intervening cycles between an instruction that produces a result and an instruction that uses it.

Initiation intervalThe number of cycles that must elapse between issuing two operations of the same type to the same unit.

Functional unitLatencyInitiation interval
Integer ALU01
Data memory (loads)11
FP add (fadd.d)31
FP multiply (fmul.d)61
FP divide (fdiv.d)2425

The adder and multiplier are pipelined, so a new operation can start every cycle (interval 1). The divider takes 25 cycles per divide, so the next divide has to wait (interval 25). The multiplier's 6 is derived from its seven stages (stages − 1), as for the adder (4 − 1 = 3).

AddedWAW example. fmul.d f1, f2, f3 is followed two instructions later by fadd.d f1, f4, f5. fmul.d writes in WB at cycle t + 8. fadd.d starts two cycles later and writes at t + 7, so it finishes first. The older fmul.d then overwrites f1, and the final value is wrong. The program order says fadd.d should have the last word.

Checks made in the ID stage

  1. Structural hazard: check that the divider is free (if this is a divide) and that the register write port will be free in the cycle this instruction reaches WB.
  2. RAW hazard: wait until the source registers are not going to be written by an instruction that will not have its result ready by the time this one needs it.
  3. WAW hazard: check that no instruction in the adder, multiplier or divider has the same destination register. If one does, hold this instruction.

Handling exceptions with out-of-order completion

  • Accept imprecise exceptions. Simple, but hard for software to recover from.
  • Delay write-back until all earlier instructions are known to be safe. Costly in hardware.
  • Keep a history or future file of register and memory updates so changes can be undone.
  • Let the handler finish the instructions already in flight, then restart at the next one.

One-page cheat sheet

AddedRevise the night before

Three designs

  • Single-cycle: CPI 1, clock = slowest instruction
  • Multi-cycle: clock = slowest step, CPI 3 to 5, units reused
  • Pipelined: clock = slowest stage, CPI about 1

Five stages

  • IF fetch, update PC
  • ID decode, read registers (fixed fields)
  • EX ALU or address
  • MEM load or store
  • WB write register

Pipeline registers

  • IF/ID, ID/EX, EX/MEM, MEM/WB
  • Hold data and control for the next stage

Performance

  • Cycles = k + n − 1
  • Speedup = nk / (k + n − 1), tends to k
  • CPI = 1 + stalls per instruction
  • Speedup = depth / (1 + stalls)

Hazards

  • Structural: same hardware
  • Data: result not ready
  • Control: branch decision late

Data hazards

  • RAW is the only one in a 5-stage pipeline
  • WAR, WAW need out-of-order or long-latency units
  • No forwarding: 2 stalls adjacent, 1 at distance 2
  • Load-use: 1 stall even with forwarding

Branches

  • Decision in MEM: penalty 3
  • Decision in ID: penalty 1
  • Stall, predict not taken, predict taken, delayed branch
  • MIPS has a delay slot, RISC-V does not

Multicycle FP

  • Latency / interval: add 3/1, multiply 6/1, divide 24/25
  • Divider is not pipelined
  • New hazards: divider, WB port, WAW, imprecise exceptions
  • Stalls = latency − independent instructions between

Numbers to remember

  • Laundry: 6 h against 3.5 h, speedup 1.71
  • 800 ps against 200 ps clock, speedup about 4
  • CPI 4.54 (branch 2), 4.78 (branch 4)
